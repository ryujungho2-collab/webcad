# HOUSE-MCP-01 · 지하+2층 단독주택과 공통 도구 연결

사용자 과제: 지하실을 포함한 지상 2층, 마당, 모듈 배치와 다른 개성을 가진 주택. 참고 건축물을 확인하고 Copilot/MCP로 실제 우리 CAD에서 작성·수정하며 필요한 연결을 구현한다.

## 구현

- `scene.layer`, `scene.objects`: 기존 레이어·이름·표시·솔리드 마감 명령을 공통 계약에 연결했다. 기하 뒤에 배치하고 native Preview/Apply/Undo 한 경계를 공유한다. 선택 밖 기존 개체, 잠긴 레이어, 없는 ID, 비솔리드 마감을 거절한다. native 생성·숨김·이름 상태를 합성해 불필요한 동일 값 명령의 거절을 피한다.
- `curve.polyline → slab.create`: 같은 제안에서 먼저 만든 닫힌 XY 외곽/홀을 native 슬래브 입력으로 허용한다. 원본은 숨겨 남기고 계단 구멍을 실제 비운다. 열린/높이가 다른/앞으로 참조한 윤곽은 거절한다.
- 실제 부재 33개 벽과 지붕·층·선큰을 조회하기 위해 `drawing.section`과 제한된 `cad.pathClearance`의 명시적 범위를 64개로 확대했다. 조회의 의미나 선택 권한은 넓히지 않았다. 카탈로그는 canonical 39, MCP bridge 3개 포함 42다.
- 레시피는 사용자 설계 과제용 도구 호출 데이터이며 CAD 원본을 직접 생성하지 않는다. 실제 공식 SDK stdio, opt-in 편집기 bridge, Copilot Review와 UI Apply로 생성했다. 외부/로컬 모델 호출은 없다.

## 과제 산출물

설계 설명과 파일 (local-only, not in repository: `output/projects/lightwell-house/README.md`). B1 -3.000, 1F ±0.000, 2F +3.300. 서쪽 선큰·현관 다리·남쪽 정원, 사선 주방 날개·L자 침실층·비대칭 경사지붕을 모델링했다. 계단·유리·프레임·가구·수목을 척도 확인용으로 둔다. 세 층 평면과 두 단면은 실제 선택 BRep에서 절단한다. 실명·가구·계단·치수는 공통 도구로 만든 편집 가능한 native 정적 주석이다. DXF·STEP·재료 GLB를 제공한다.

## 검증 방법

전체 단위 검사 1,610개, 최신 이동/조회 검사 4개, production build/architecture 검사를 통과했다. `gardenHouse.browser.tsx`는 실 stdio로 각 제안의 미게시→UI Apply→영수증을 확인하고 부재 전부의 양수 체적·BRep 유효성, 독립 계산한 지하 슬래브 체적·레벨, 계단 홀 체적, 실제 절단·출력·재열기를 검사한다. 현관 문 폭 1300에서 1400으로 내부 코파일럿을 통해 바꾸고 독립 벽 체적 변화·명시 벽 경로 여유·단일 Undo를 확인한다. 이 테스트의 브라우저 산출물은 재열기 동안 대형 GLB를 담기 위해 테스트 전용 IndexedDB에 보관한다. 제품의 저장 방식을 우회하거나 바꾸지 않는다.

## 평가 범위

과제의 실제 생성·수정·조회·파일 증거가 남았다는 뜻이다. 자율 주거설계 추론, 미적 판단, 실/층/계단 의미 관계, 자동 인접 관계 기반 벽 접합, hosted 창호 제품, 구조·지반·방수·배수·법규·머리높이 검증은 구현 완료로 간주하지 않는다. 기존 졸업설계 과제의 미달 판정을 바꾸지 않는다.


## 사용자 피드백 이후 벽·외벽·내부 보완

벽을 개별 맞대기 호스트로 두어 생긴 모서리를 명시적 마이터 각도로 수정했다. 일반 native 벽 정의·검증·커널 footprint·벽 편집 패널과 같은 MCP `wall.create/update`에 연결했다. 원본 중심선 끝점 수정도 호스트 선택 아래 Preview/Undo로 처리한다. 벽 수정에서 기존 `solidFinish`가 사라지던 문제를 고쳤다. 마이터의 바깥 삼각 영역을 벽 통과 거리 계산에도 포함하고 파일 v49로 의미를 보존한다. 실제 두 벽 합집합의 체적으로 틈·중복이 없음을 검증하며 기존 v41 파일은 계속 읽는다.

과제에서는 1층 세탁실 옆 325mm 틈, 팬트리·지하 욕실/설비실의 빠진 구획, T/L 끝점과 문 위치를 수정했다. 단순 사각 기호를 숨겨 남기고 문 여닫이·창호·침구·소파 좌석·식탁 의자·위생기구·계단 방향을 native CAD 요소로 새로 작성한다. 실제 내부 부재도 상판/다리·소파/좌석·침구로 분리한다. 외벽은 개구부를 가진 독립 native 외장 벽과 별도 창턱·후드·기단·층간 띠다. 외벽 추가 후 기존 다섯 도면의 원본 범위를 바꾸도록 `drawing.section.replaceExisting`을 연결했고, 선택·기존 view ID·출력 레이어·native 잠금과 Undo를 유지했다.


추가 평면 검토에서 발견한 1층 WC/세탁기, 2층 욕실 문/샤워와 침실 3 침대/책상 간섭을 별도 MCP 이동 패스로 수정한다. `scene.objects.objects[].delta`는 선택한 독립 부재와 명시한 정적 도면 기호를 native Move로 같은 검토에서 옮긴다. 기존 마감·부피를 유지하고 Undo/Redo를 공유하며, 소유된 단면선/투영선/스케치 일부의 임의 이동은 거절한다. `cad.measure`는 실제 변환한 직선·직선 polyline·rectangle의 world bounds도 반환해 2D 기호와 3D 부재의 XY 일치를 확인한다. 각도 곡선에 샘플 기반 bbox를 정확한 값으로 추가하지 않는다.


최종 결과는 [검증 manifest](../verification/HOUSE-MCP-01-2026-10-24.json)에 파일 SHA-256과 함께 기록했다. 실제 브라우저 과제는 base 22개, 벽·외벽·내부 보완 47개, 배치 간섭 수정 16개를 각각 통과했다. 공통 MCP 24개, native 건축 29개, 기본 CAD 도구 19개, 고급 CAD 도구 17개 회귀도 통과했다. 도면과 모델은 실제 화면을 열어 확인했고, 사용자 앱에 독립 **틈마당집 · B1 + 2F** 프로젝트로 가져왔다. 검토 뷰어는 화면/카메라가 바뀔 때 렌더링하도록 해 정지 화면에서 계속 GPU를 사용하지 않는다.
