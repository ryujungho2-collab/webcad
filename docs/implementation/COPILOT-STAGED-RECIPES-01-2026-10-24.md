# COPILOT-STAGED-RECIPES-01 · 단계형 계획과 검증된 부품 템플릿

2026-10-24. 자연어 CAD의 일반 코파일럿에 질문·답변 재개와 파라미터 템플릿을 연결했다. 모델의 비공개 추론 내용을 표시하거나 학습하는 방식이 아니라, 필요한 입력·명시된 기본값·실행 가능한 제안·검증 결과를 분리한다.

## 실행 흐름

1. 의도와 편집 대상을 확인한다. 선택되지 않은 기존 객체를 조회했다고 편집 권한을 얻지는 않는다.
2. 템플릿은 이름·형상 범위·필수 숫자 필드·단위·한도를 제공한다. 모델은 키워드만으로 매칭하지 않도록 지시받는다.
3. 빠진 필드는 한 번에 최대 3개 질문으로 반환한다. 앞서 입력한 값은 유지하며, 모든 질문에 답해야 다음 계획으로 진행한다. 치수 기본값을 임의 생성하지 않는다. 길이 입력 단위는 mm/cm/m, 개수는 정수다. 템플릿 답변은 `템플릿 · 통풍 덮개 가로 100mm …`처럼 읽을 수 있는 문장으로 이어지며 모델의 재해석 없이 검증된 필드로 컴파일한다.
4. 모델이 위치·참조 면 등 의미상 모호성을 발견하면 명시적 질문 응답을 반환할 수 있다. 질문과 실행 명령을 한 응답에 섞으면 거부한다. 실제 면/모서리 후보는 기존 조회 도구로 확인하고, 답변은 원 요청과 함께 다음 요청으로 보낸다.
5. 템플릿은 일반 스케치·변수·바인딩·돌출 또는 프리미티브 명령으로 컴파일된다. 별도 메시 모델/임의 스크립트 실행은 없다.
6. 원본과 분리된 실제 커널 미리보기 후 템플릿 결과의 체적을 독립 계산식과 비교한다. 차이가 `max(0.01 mm³, expected × 1e-7)`를 초과하거나 형상이 유효하지 않으면 Apply를 막는다.
7. 사용자가 검토한 제안만 한 Undo로 적용한다. 프롬프트·문서·선택·레이어·작업 평면·모델 설정 변경은 기존 문맥 검사로 질문과 제안을 무효화한다.

자체 평가한 확신도 점수는 진행 권한으로 사용하지 않는다. 필수값 유무, 참조의 실제 존재, 치수/형상 제약, 커널 결과가 판단 근거다. 조회 반복·타임아웃·취소·선택 제한은 기존 gateway 루프를 재사용한다. 생성 전에는 알 수 없는 면 번호를 추측해서 후속 도구를 잇지 않는다. 그 단계는 먼저 적용한 뒤 실제 형상을 조회한다.

## 등록된 v1 템플릿

| ID | 범위 | 필수 파라미터 |
| --- | --- | --- |
| `mounting-plate` | 기존 검증된 직사각형 4홀 플레이트 | width, depth, thickness, margin, holeDiameter |
| `pin` | 머리·나사산·테이퍼가 없는 원통 핀 | diameter, length |
| `vented-lid` | 평평한 직사각형 판과 등간격 원형 관통구 그리드 | width, depth, thickness, margin, holeDiameter, rows, columns |

공통 배치 기본값은 월드 XY 원점, +Z 방향이다. 선택 면에 자동 부착하지 않는다. 플레이트/덮개의 XY 원점은 외곽 좌하단, 핀은 밑면 중심이다. 이 기본값은 검토 요약에 표시한다. 덮개의 margin은 **구멍 중심과 외곽 사이 거리**이며 한 행/열은 해당 축 중앙에 둔다. 행/열 각각 1–16, 전체 최대 64개다. 구멍이 서로 또는 외곽에 닿으면 거부한다. 길이는 0.01–10000 mm 범위다.

통풍 덮개는 원본 스케치와 길이 변수의 관계를 유지한다. 폭 수정 시 외곽 구멍 여백을 유지하고 안쪽 구멍을 등간격으로 재배치한다. 행/열 개수 변경은 기존 부품의 길이 파라미터 편집 범위가 아니며 새 템플릿 계획이 필요하다.

내부 엔진 예시:

```text
통풍 덮개
핀 지름 6mm 길이 30mm
통풍 덮개 가로 100mm 세로 70mm 두께 3mm 중심 여백 12mm 구멍 지름 6mm 행 3 열 5
```

첫 예시는 질문부터 시작한다. 내부 언어 문법은 제한된 명시 필드 파서다. 추가 형상 요구·중복 치수·지원하지 않는 단위를 조용히 버리지 않는다. 자유로운 문장 해석과 면 선택 판단은 연결된 모델이 담당하며, 모델이 언제 질문해야 하는지의 의미적 정확성까지 결정론적으로 보장하지 않는다.

## Gateway 계약

기존 `{version:1,toolCalls:[...]}`와 command 제안은 유지한다. 요청에 서버 소유 `recipes` 카탈로그와 `planning` 단계 설명을 더한다. 새 응답은 둘 중 하나다:

```json
{"version":1,"recipe":{"id":"pin","parameters":{"diameter":6,"length":30}}}
```

```json
{"version":1,"clarification":{"summary":"기준 면이 필요합니다","questions":[{"id":"face","prompt":"어떤 면을 기준으로 할까요?","options":["윗면","앞면"]}]}}
```

`recipe.parameters`는 이미 확인한 일부 필드만 반환할 수 있다. 클라이언트가 누락 필드를 질문한다. 질문은 1–3개, 선택지는 0–3개이며 자유 입력을 허용한다. 로컬 Ollama의 JSON 출력 schema와 지침도 같은 응답 계약을 사용한다. 임의 recipe ID·추가 파라미터·명령 혼합 응답은 거부한다. 이 릴리스는 canonical/MCP 도구 수를 늘리지 않으며 MCP용 recipe 호출 인터페이스는 추가하지 않았다.

## 검증 및 한계

- 전체 Node 1625/1625 통과. 신규 8개 테스트는 단위 변환, 질문 재개, 충돌/범위/응답 혼합 거부, 실제 커널 체적, 폭 수정에 따른 15개 구멍 관계, 직렬화·Undo/Redo, gateway 조회→질문, 서버 소유 schema를 확인한다.
- 실제 React/Worker 브라우저 14개 검사: 빈 문서에서 3회 질문→15홀 덮개 미리보기→Apply→Undo/Redo, 문맥 변경 무효화, 모델 질문/답변 경로를 확인했다.
- 기존 gateway 13개·대화 생성/수정 15개 UI 회귀 검사도 통과했다. 빌드/타입 검사와 804개 모듈의 아키텍처·문서 링크 검사를 통과했다. 기존 번들 크기 경고는 유지한다.
- 브라우저 모델 응답과 Ollama 응답은 통제된 fixture다. 실제 LLM의 자유 문장 성공률을 측정한 결과가 아니다. CAD 형상은 실제 커널로 생성한다.
- 브라우저 검사 기록 (local-only, not in repository: `output/verification/copilot-planning/browser-report.json`), 생성 문서 (local-only, not in repository: `output/verification/copilot-planning/lid.webcad.json`), 화면 (local-only, not in repository: `output/verification/copilot-planning/lid.png`), Node 로그 (local-only, not in repository: `output/verification/copilot-planning/node-tests.log`).
- 브래킷, 덮개 턱/슬롯, 나사산, 조립체, Blender 연산은 이 템플릿 묶음의 범위가 아니다. 일반 도구 조합과 별도 형상 검증이 필요하다. 체적 일치만으로 제조/구조 적합성을 주장하지 않는다.

## 더 나은 확장 방향

프롬프트를 길게 늘리기보다 **형식화된 설계 요구 → 검증된 매크로/도구 그래프 → 실제 형상 피드백**을 중심으로 확장한다. 선택 면의 의미와 영속 참조, 작업 간 선행조건을 다음 계획에도 보존하고, 매크로마다 치수 경계값·기하 관계·왕복 저장 검증을 갖춘다. 수정 실패 시에는 제약을 몰래 완화하지 않고 제한된 재계획 또는 질문으로 돌아간다. 브래킷도 형상 유형(평판/L형/U형), 두께, 굽힘/필렛, 볼트 패턴 의미가 확정된 템플릿부터 등록하는 편이 적절하다. 이를 고정된 다음 작업 순서로 취급하지 않는다.
