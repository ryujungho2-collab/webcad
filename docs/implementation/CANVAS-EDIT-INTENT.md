# 캔버스 수정 의도와 영향 검수

> 단계 기록: 아래 구현·검수 수치는 해당 시점의 근거다. 최신 지원 범위는 [CAD-BASICS](../product/CAD-BASICS.md), 최근 전체 검수는 [PROJECT-STATE](../../PROJECT-STATE.md), 다음 실행 순서는 [NEXT-STEPS](../../NEXT-STEPS.md)를 따른다.

2026-10-03. 사용자의 우선순위는 실무자가 수정할 대상과 유지할 관계,
변경 영향을 캔버스에서 이해하고 제어하는 CAD 조작 경험이다.
이 문서는 구동 치수 편집 흐름의 구현과 검수 범위를 기록한다.
드래그·핸들에도 같은 검토 흐름을 연결했으며, 후속 구현·전체 검수와 경계는
[DIRECT-EDIT-EXPERIENCE.md](DIRECT-EDIT-EXPERIENCE.md)에 기록한다.

## 실제 편집 흐름

- 치수 선택 시 값의 구동 원본을 표시한다. 일반 치수는 단위 값,
  단일 변수에 연결된 치수는 그 변수 정의, 복합 식에 연결된 치수는
  바인딩 식을 편집한다. 변수의 전체 연결 값에 영향이 있음을 명시한다.
- 입력 후 공용 Preview 실행기가 분리된 문서에서 스케치를 풀고 연결
  솔리드를 실제 커널로 재생성한다. 기존/예상 윤곽을 캔버스에 함께 표시하고,
  유지·변경·해제할 구속과 파생 변수, BRep 체적 변화를 보여준다.
  치수 레이블도 현재 → 예상 값을 구분하며, 해제할 관계는 Apply 전까지 표시한다.
- 관련 관계에 포커스하거나 포인터를 올리면 실제 대상 형상을 강조한다.
  선택 대상의 관계를 우선 표시하며 전체 관계도 펼칠 수 있다.
  자유도는 스케치 전체의 해석 결과이며 개별 형상의 자유도로 표시하지 않는다.
- 편집창은 검토 형상 주변의 여유가 더 큰 가장자리에 배치하고 캔버스 안에서
  스크롤한다. 검토 정보를 접으면 예상 윤곽을 유지하며 도면을 더 넓게 볼 수 있다.
- Apply는 화면에서 검토한 동일 제안을 한 번의 History에 적용한다.
  Esc/Cancel은 문서와 History를 바꾸지 않는다. Undo/Redo 등 다른 편집이
  발생하면 예상 윤곽을 지우고 Apply를 막으며, 사용자가 Refresh해야 다시 평가한다.

## 충돌의 제어

변수 변경으로 발생한 충돌도 구조화된 스케치·구속·형상 ID로 전달한다.
실패한 입력은 문서에 남기지 않고 관련 치수/형상을 강조한다. 사용자는
충돌 치수를 편집하거나 `Preview release`로 해제할 관계를 선택할 수 있다.
해제할 구속과 함께 사라질 바인딩을 검토하고, 실제 해석에 통과한 경우에만
해제와 원래 수정을 한 트랜잭션으로 Apply한다. `Keep all constraints`는
해제 제안을 취소한다. 구속을 자동으로 완화하거나 삭제하지 않는다.

솔버가 반환하는 항목은 잔차가 남는 충돌 관계이며 유일한 원인/최소 제거 집합을
보장하지 않는다. 다른 스케치의 충돌은 이 편집창에서 임의로 해제하지 않는다.
후속 피처 재생성 실패는 별도 진단으로 소스/출력 ID를 유지한다.

## 검수

구멍 4개가 있는 판의 폭 100 → 120mm를 캔버스에서 변경한다.
원점, 높이 60mm, 가장자리 여백 10mm, 구멍 지름 8mm를 유지하며
구멍 중심과 간격이 전파되고, 두께 8mm 솔리드의 체적을 독립 공식
`(폭 × 높이 - 4π × 4²) × 8`과 비교한다. 허용 오차는 문서 선형 공차와
경계 길이에서 전파하며 화면 반올림과 해석값 검사를 구분한다.

- 새 Node 검사 4개: 단위/변수/식 구동 원본, 분리된 해석 결과의 변경 불가,
  실제 체적, 충돌 진단, 명시적 해제, 정확한 한 Undo/Redo, 취소·오래된 제안 차단.
- 새 `canvasIntent` 브라우저 과제 27개: 두 패널을 숨긴 실제 React/Worker 흐름,
  원래/예상 윤곽과 관계 강조, 체적, 잘못된 단위·순환 관계,
  접기/펼치기, 실제 포인터 선택·확정·해제와 캔버스 내 배치, 완전한 Undo/Redo.
- 기존 치수 검사는 Apply 전에 실제 미리보기 완료를 기다리도록 변경했다.
  기존 point 과제는 명령 종료 후 Draw 탭에 명시적으로 진입한다.
  결과 형상과 관계·History 검사 기준은 유지한다.
- 치수 편집 시점에는 전체 Node **348개**, 9개 브라우저 과제의 **152개 UI/Worker
  검사** 및 빌드를 검수했다. 직접 편집 후 전체 결과는 위 후속 문서에 있다.

```powershell
pnpm --filter @agent-webcad/web test
pnpm --filter @agent-webcad/web test:browser
pnpm --filter @agent-webcad/web test:browser --page=canvasIntent --artifacts
pnpm build
git -c core.safecrlf=false diff --check
```

실제 검토 화면은 [예상 형상](../../output/images/canvas-dimension-preview.png)과
[충돌 제어](../../output/images/canvas-dimension-conflict.png)에 있다.
기존 chunk 크기 경고는 남는다. 이 검수는 실무자의 작업 시간이나 학습 비용,
기존 CAD 대비 우수성을 입증하는 사용성 실험이 아니다.

## 다음 우선순위와 경계

이번 예상 윤곽은 활성 스케치의 2D 형상이다. 종속 솔리드는 실제 재생성과
체적 변화를 검토하지만 3D 솔리드 자체의 전후 ghost는 아직 제공하지 않는다.
직접 드래그·핸들은 같은 검토 UI와 Preview/Apply로 연결했다. 요청 윤곽과
검증 윤곽, 치수 유지/구동 원본 조절, 명시적 해제의 범위는 후속 문서에 있다.
고정점 좌표는 관계 확인·해제는 가능하지만 이 창에서 x/y를 직접 편집하지 않는다.
대형 스케치의 입력 지연·프레임 성능도 별도 측정이 필요하다.

**구속에 따라 움직일 수 있는 방향/경로 안내와 드래그 제어**도 구현했다.
현재 검수와 국소 해석 경계는
[CONSTRAINT-GUIDED-DRAG.md](CONSTRAINT-GUIDED-DRAG.md)에 있다.
다음은 겹치는 객체/
서브 요소 선택과 반복 명령 흐름을 실무 과제로 평가한다. 구멍 판 규격 수정과
건축 도면 구간 변경의 작업 시간, 재시도, 패널 이동 횟수를 측정할 기준을 만든다.
live Mirror/Pattern, 정의/인스턴스, AI와 mesh 확장은 이 CAD 경험을 안정화한
뒤의 제품 확장으로 유지한다.
