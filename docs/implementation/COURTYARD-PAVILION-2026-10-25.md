# 중정 파빌리온 재작업과 A1 판넬

기존 공간 곡선 파빌리온은 3개 스윕과 두꺼운 타원 로프트의 기하 검증에 치우쳤다. 사용자 피드백으로 해당 안의 건축적 완성 판단을 철회하고, 실제 머무름과 진입·그늘·뜰의 관계를 가진 다른 개념 모델을 작성했다.

새 모델은 두 개의 폭·높이 가변 캐노피, 동측 연결 지붕, 14개 C2 XYZ 집성목 프레임, 연속 기단, 세 곳의 곡선 좌석, 중앙 수공간과 두 인체 스케일로 이루어진 27 솔리드다. 첫 눈높이 검토에서 처마 밖으로 노출된 프레임 끝을 발견해 끝 프레임을 종방향 320 mm 물리고 캔틸레버 끝을 지붕 안쪽으로 수정했다. 인체 판도 진입 방향을 향하도록 바꿨다.

실제 SDK stdio MCP → 공통 도구 → native detached Review → 사람 UI Apply 경로로 생성했다. 제품 명령 우회나 JSON 직접 모델 작성은 사용하지 않았다. 27개 BRep 유효성, 14개 프레임의 독립 자연 cubic 경로 적분 × 사각형 면적, 실제 평면·횡단면 출력과 no-model-endpoint를 확인한다. 3D 파일과 연관 도면 파일은 같은 원본 모델의 두 가지 정규 프로젝트 산출물이다.

실무 크기의 단면 작성 도중 공통 대상 선택기 10개 한도와 단면 도구의 64개 입력 한도가 맞지 않음을 확인했다. 선택기를 64개 명시 대상으로 확장했다. 편집 권한은 여전히 사람이 선택한 가시·잠금 해제 대상에 한정되며 각 도구의 자체 입력 한도는 유지한다.

큰 결과 전송에서 약 67 MB의 테스트 산출물 JSON이 기존 64 MB HTTP 한도를 초과했다. 해당 run의 79개 기능 assertion과 결과는 recovery fixture로 회수했고, 원래 전달 오류도 보존했다. 이후 보고 전송은 1 MB 이상에서 gzip을 사용한다. 압축 수신은 64 MB, 해제 결과는 192 MB로 계속 제한한다. 최종 재작성 run에서 같은 크기의 전체 아티팩트 전달까지 다시 확인한다.

판넬은 A1 가로 841 × 594 mm다. 실제 CAD BRep tessellation과 source transform / solidFinish로 만든 외부·진입·내부·정투영 뷰, 실제 BRep 횡단면 SVG를 사용한다. 판넬용 단면 선은 가독성을 위해 색과 인쇄 굵기만 조정하며 좌표·형상은 바꾸지 않는다. 수공간·진입축·재료·단면 높이를 설명하고 구조 안전이나 미적 점수를 자동 판정하지 않는다.
