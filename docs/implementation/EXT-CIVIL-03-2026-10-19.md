# EXT-CIVIL-03 대형 도면 가져오기·진행·취소

2026-10-19. 2차와 같은 Civil_projects 변환 DXF(7,299,755 bytes)를 검증 입력으로 사용했다. 해치 지원 범위는 2차와 같다.

## 변경

- 검토용 분리 문서의 batch 준비를 약 16ms 작업 구간에서 브라우저에 양보한다. 준비/일반 기하 미리보기/블록 미리보기 단계와 처리 개수를 `role=status`, live region, progress로 표시한다. 전체 완료 시간을 추정하는 백분율은 표시하지 않는다.
- 취소·Escape·설정 변경·닫기에서 AbortSignal로 준비 작업을 중단하고 임시 계획을 폐기한다. live 문서와 Undo 기록은 바꾸지 않는다. Apply 대기 중에도 취소할 수 있고, 게시 직전에 signal과 문서 버전을 재검사한다. 실제 게시 구간은 동기·원자적이며 완료 후에는 Undo를 사용한다.
- 모델 탐색기는 처음 100행을 만들고 100행씩 더 볼 수 있다. 검색은 모든 객체를 대상으로 한다. 작은 선택(100개 이하)은 페이지 밖의 선택 행도 표시하며 큰 선택에서는 주 선택 행을 표시한다. 표시 제한은 객체·선택 자체를 제거하지 않는다.
- 다중 선택 속성 패널이 같은 의존성 인덱스를 객체마다 새로 만들던 부분을 한 번 생성해 재사용한다. 선택 속성/문맥 도구/전체 맞춤도 feature lookup 인덱스를 공유해 반복 전체 탐색을 줄인다.

## 검증

실제 파일은 객체 4,817개, 블록 91개, 표시 배치 894개와 문자 98개를 유지한다. Chrome/SwiftShader에서 물리 Apply 클릭부터 검토 창 종료까지 2차 37,370.4ms, 3차 집중 검증 16,014.9ms(약 57% 감소)를 관측했다. 중간 변경은 23,104.7ms였다. 동일 입력의 단일 실행 관측이며 캐시·동시 부하를 엄격하게 통제한 벤치마크 또는 고정 SLA가 아니다. 검토 준비는 약 2초, 관측 viewport sync는 약 243ms였다.

Node 취소 테스트는 준비 중 취소, queued Apply 취소, 같은 계획 재시도·한 번 Undo/Redo, 만료 계획/이미 취소된 signal 거절을 검증한다. 브라우저는 실제 버튼으로 12,000개 선의 준비 취소·재시도, 단일 Undo/Redo, 100행/더 보기/페이지 밖 선택/전체 검색을 검증했다. 역사·다중 선택 회귀는 23개 통과했다. 처음에는 페이지 밖의 두 번째 선택 행이 보이지 않아 회귀가 실패했고 작은 선택을 추가 표시해 수정했다.

전체 Node 1,503개, 진행/취소 브라우저 11개, 실제 파일 집중 검사 6개, DXF workflow 18개, preparation 25개, history/selection 23개 통과. 속성 패널 28개·선택 도구 23개·실제 파일 전체 workflow 16개도 통과해 브라우저 합계는 150개다. 실제 전체 검사는 문자 편집/Undo·Redo·v48 재열기·A3 SVG/Worker PDF까지 완료했고 Apply는 15,601.6ms로 관측됐다. Build·TypeScript·architecture 713 modules 통과.

## 남은 경계

파일 읽기·DXF parse 및 일부 최종 검증/직렬화는 동기 작업이므로 모든 구간의 즉시 취소를 보장하지 않는다. 게시 이후 화면 생성은 Undo로 되돌린다. 대형 선택과 후속 편집의 지연은 추가 개선 대상이다. 기존 Edge 대형 파일 입력 timeout은 해결했다고 주장하지 않는다. 최초 전체 브라우저 실행은 문자 편집 후 Undo 입력 timeout으로 중단됐으며 그 실패 기록도 보존했다. 인덱스 수정 후 최종 전체 16개 검사는 통과했다. 해치 gradient 11개·곡선 경계 4개 제외와 외부 DWG 변환의 한계는 [2차 기록](EXT-CIVIL-02-2026-10-19.md)을 따른다.
