# 캔버스 대상 확인과 연속 편집

> **현재 기능 설명:** [정밀 작도와 편집](../features/DRAWING-EDITING.md). 이 문서는 날짜별 구현·설계 기록이며, 아래 사용법·제한·수치는 당시 범위다. 후속 지원은 대표 가이드를 따른다.

> 단계 기록: 아래 구현·검수 수치는 해당 시점의 근거다. 최신 지원 범위는 [CAD-BASICS](../product/CAD-BASICS.md), 최근 전체 검수는 [PROJECT-STATE](../../PROJECT-STATE.md), 다음 실행 순서는 [NEXT-STEPS](../../NEXT-STEPS.md)를 따른다.

결정일: 2026-10-03. `NEXT-STEPS.md`의 두 후보 중 **캔버스에서 설계 의도를
확인하고 편집하는 경험**을 먼저 개선했다. live Mirror/Linear·Radial Pattern과
편집 가능한 정의/인스턴스의 확장 순서는 유지한다.

구동 치수, 변수 전파, 구속에 맞는 드래그와 실제 Preview/Apply는 이미 있다.
남은 조작의 단절은 겹친 원본을 선택하기 어렵고, 표시된 핸들을 키보드로
찾아 편집한 뒤 같은 위치에서 다음 수정을 이어갈 수 없다는 점이었다.
반복 배치와 재사용 정의도 이 원본 선택·수정 흐름을 사용하므로 먼저 연결했다.

## 구현한 경험

- Direct 모드에서 겹친 다른 원본을 클릭하면 점/변/곡선 후보를 모두 보여준다.
  같은 원본의 인접 변으로 이미 선택한 핸들이 바뀌지 않는다. 선택한 핸들과
  겹친 다른 원본은 Alt+click으로 다시 고를 수 있고, 포인터의 후보 배지도
  목록을 연다. 허용 범위는 화면의 12px이며 곡선 샘플 사이의 표시 선도 검사한다.
- 후보를 가리키거나 방향키로 탐색하면 해당 원본 윤곽, 정확한 점/변, 관계로
  연결된 형상을 강조한다. 원본 이름, 핸들 역할, 스케치/평면과 실제 원본의
  관계를 표시한다. 긴 후보 목록만 스크롤하고 관계 설명과 선택/취소 안내는
  계속 보인다. Enter/클릭은 선택만 변경하고 도면과 Undo를 변경하지 않는다.
- 선택한 원본의 보이는 점과 변 중점이 하나의 키보드 탐색 그룹이 된다.
  캔버스의 Tab으로 진입하고 방향키/Home/End로 탐색한다. 탐색 순서는
  안정적인 목록 순서이며 화면의 상하좌우에 가장 가까운 핸들을 고르는 방식은
  아니다. 화면 밖의 핸들은 제외한다. Esc는 캔버스로 돌아간다.
- Enter/Space로 현재 핸들의 정밀 편집을 열면 좌표 입력에 포커스를 둔다.
  구속의 허용 방향과 단위 입력, 실제 해석된 예상 형상·변수·종속 솔리드 영향,
  명시적인 충돌 제어를 기존 드래그와 같은 흐름으로 사용한다. Tab으로 다음
  좌표에 이동하고 Enter로 검토한 제안을 적용한다. 적용/취소 뒤에는 동일한
  원본과 영속 핸들로 포커스를 돌려 반복 수정을 이어간다.
- 캔버스는 실제 키보드 포커스를 받을 수 있다. Direct 모드의 캔버스에서
  Ctrl/Meta+Z와 Y로 도면 Undo/Redo를 사용할 수 있다. 좌표 입력에서는
  키 입력과 텍스트 Undo가 편집기에 속하고 CAD 도면의 이력으로 전달되지 않는다.
- 후보의 정체성은 원본 객체 + 종류 + 영속 topology ID다. 서로 다른 원본에
  같은 점 ID가 있어도 바꿔 붙이지 않는다. 문서 변경 시 후보 선택을 폐기하고
  캔버스로 포커스를 돌린다. 숨김/잠긴 레이어와 형상은 새 후보에서 제외한다.
  문서 변경 알림도 앱의 화면 갱신에 연결해 외부 명령 뒤의 오래된 후보를 막는다.
- 반복 Copy의 자체 확정은 세션의 기준 revision과 화면 갱신을 함께 처리한다.
  확정 알림이 먼저 도착해서 반복 명령을 끝내지 않으며, 외부 변경은 기존처럼
  세션을 취소한다. 핸들/마우스 편집을 닫을 때 캔버스 포커스도 복원한다.
- 구속을 명시적으로 해제한 적용 직후에도 검토 당시 원본의 설명을 사용한다.
  이미 삭제된 구속을 다시 읽어 화면이 사라지는 문제를 막고 편집 종료·Undo
  UI가 정상적으로 남는지 기존 캔버스 치수 과제에서 검사한다.

목록의 **원본 관계**는 그 형상이 참여하는 관계다. 모든 관계가 해당 핸들의
이동을 막는다는 뜻은 아니다. 편집 시작 뒤의 허용 방향은 핸들별 자유도와
실제 해석을 사용하며 자세한 정책은
[CONSTRAINT-GUIDED-DRAG.md](CONSTRAINT-GUIDED-DRAG.md)에 있다.
선택과 포커스는 문서 밖 UI 상태이며 새 피처나 구속을 저장하지 않는다.

## 실제 검수

기계 과제는 변수로 구동되는 100×60×8 판과 네 관통 구멍이다. 캔버스에서
코너를 키보드로 찾아 120×80mm로 바꾸고 네 구멍의 전파와 실제 Worker 체적
`(120×80 − 64π)×8`을 독립적으로 검사한다. 같은 start/end/edge ID를 사용하는
세 겹친 선을 추가해 두 번째 원본을 선택하고, 그 원본의 수평 관계에 따라
대각선 요청을 제어한 뒤 다른 두 원본이 그대로인지 검사한다.

- `directSelection.test.ts`의 기존 우선순위·가시성 검사를 유지하고 세 원본의
  겹침, 화면 공차와 곡선 표시 구간 선택 **3개**를 추가했다. 기존 참조 검사도
  의미 있는 핸들 명칭, 잘못된 종류, 잠긴 레이어를 확인하도록 개선했다.
- `directTargetExperience` **28개 UI/Worker 검사**는 격리 브라우저의 실제
  키보드/텍스트/마우스 입력을 사용한다. Tab/방향키/Space/Enter, 단위 입력,
  실제 예상 형상과 BRep 체적, 동일 핸들 복귀, 도면·텍스트 Undo 분리, 완전한
  Undo/Redo, 후보 hover/키보드 선택, 세 원본의 ID 충돌, 선택된 핸들의 실제
  드래그, Alt 선택, 오래된 후보/숨김 갱신과 모드 변경을 검수한다.
- 기존 `commandExperience`의 실제 포인터 복사 검사를 좌표·이력뿐 아니라
  반복 세션/원본 기준점/예상 형상 유지까지 확인하도록 개선했다. 외부 변경은
  세션을 폐기하고 Undo 후 되살아나지 않는 검사도 추가해 **27개**가 됐다.
- 전체 Node **378개**, 12개 브라우저 과제 **243개 UI/Worker 검사**,
  워크스페이스 빌드와 `diff --check`가 모두 통과했다. 기존 큰 chunk 경고는 남는다.

```powershell
pnpm --filter @agent-webcad/web test
pnpm --filter @agent-webcad/web test:browser --artifacts
pnpm build
git -c core.safecrlf=false diff --check
```

## 다음 판단 기준과 경계

다음은 기계·건축의 반복 수정 과제로 작업 시간, 재시도, 확정 횟수, 패널 이동과
큰 문서의 입력→예상 형상 지연을 측정하고 가장 큰 병목을 먼저 개선한다.
후보 계산/화면 갱신 비용과 큰 연결 스케치의 해석 비용도 분리해 측정한다.
아직 실무 CAD와의 경험 동등성·우수성을 검증한 사용자 비교 결과는 없다.

이번 명확한 후보 목록과 키보드 핸들은 2D drawing/sketch 원본을 대상으로 한다.
기존 BRep 선택은 유지하며 3D 실체의 후보 목록·변형 핸들·전후 ghost, mesh 편집,
곡선 몸체의 직접 변형은 이번 범위에 없다. 현재 허용 방향/충돌과 정확한 제안
검증의 경계를 유지한 채 다음 재사용 자동화와 AI 명령으로 연결한다.
