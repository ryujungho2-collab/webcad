# COPILOT-2D3D-01 자연어 2D 생성 → 3D 변환 → 다듬기 검증

2026-10-19. 기존 Local rules·공통 CAD 도구를 한 연속 작업으로 검증했다. 이번에 제품 런타임 코드는 수정하지 않았다. 추가한 것은 실제 경로의 회귀 검사·브라우저 시나리오·파일 독립 재검사와 증거 기록이다.

## 실제 사용자 경로

빈 문서에서 **2D → Copilot → Local rules**로 시작한다. 각 요청은 **Plan → 기하/영향 검토 → Apply**한다.

1. `80x50 사각형 스케치` — XY 위 80×50mm, 원점 고정과 두 치수 구속을 가진 편집 가능한 스케치를 만든다.
2. **3D로 화면 전환** 후 `선택한 윤곽 20mm 돌출` — 선택을 다시 지정하지 않고 같은 2D 프로파일로 3D 솔리드를 만든다.
3. `윗면 중심에 지름 6mm 관통 구멍` — 적용한 결과가 다음 대상으로 선택되고 실제 면 조회를 통해 중심 관통 구멍을 만든다.
4. `수직 모서리 반지름 2mm 필렛` — 구멍을 가진 결과의 모서리를 조회해 마감하고 원본을 입력으로 보존한다.

각 단계는 한 Undo다. 원본 2D 스케치·돌출·구멍·필렛이 관계로 연결되며 이전 입력은 보존하고 최종 결과만 표시한다. 이는 2D 이미지를 3D 모양으로 바꾸는 것이 아니라 2D CAD 프로파일에서 BRep 모델을 생성하는 경로다.

## 확인한 결과

- 빈 2D 문서의 생성 Review와 3D/구멍/필렛 Review가 적용 전 문서·이력을 바꾸지 않는다.
- 2D→3D 전환은 뷰만 변경하고 원본/선택 인계가 유지된다. 2D는 고정점·가로·세로 세 구속을 가지며 기존 스케치 편집 도구에서 편집 가능한 원본이다.
- 돌출 입력은 최초 스케치 프로파일이며, 구멍은 원본 면에, 필렛은 구멍 결과에 연결된다.
- 100mm 필렛처럼 불가능한 마감은 오류와 비활성 Apply로 차단되며 중간 형상·이력은 남지 않는다. 정상 마감 Preview의 Clear도 원본을 유지한다.
- 마지막 마감 Undo/Redo가 원래 구멍 솔리드/동일 마감 정의와 참조를 복원한다.
- 실제 페이지 reload 후 문서가 revision을 제외하고 일치하고, 원본 그래프와 정확 체적을 다시 계산할 수 있다.
- 실제 브라우저가 STEP를 출력했고, 별도 Node 검사에서 STEP를 재수입해 유효성·치수·체적과 저장 원본 관계를 확인했다.

| 단계 | 독립 체적 기준 mm³ |
| --- | --- |
| 돌출 | `80*50*20 = 80000` |
| Ø6 관통 구멍 | `80000 - pi*3²*20` |
| 수직 모서리 R2 필렛까지 | `(80*50 - (4-pi)*2²)*20 - pi*3²*20 = 79365.8407346412` |

체적 허용 오차는 0.005mm³, STEP bbox는 `[0,0,0]..[80,50,20]`에서 0.001mm다. STEP 재수입은 동일 OCCT 커널의 파일 왕복이며 기대식은 독립 해석식이다. 다른 커널 전체 동등성 검증은 아니다.

신규 연속 작업을 포함한 관련 Node 21개, 실제 React/Worker와 물리 브라우저 입력 검사 18개 통과. TypeScript와 architecture 731 modules 통과. 제품 코드 변경이 없어 전체 Node/빌드를 반복하지 않았다. 이전 전체 Node 1,532·브라우저 78 검사는 [앞선 대화 연결](COPILOT-CONVERSATION-01-2026-10-19.md)의 결과다.

최초 브라우저 검사는 잘못된 필렛에서 Apply가 없어져야 한다고 가정해 실패했다. 실제 제품은 오류를 설명하고 Apply를 비활성화하므로 검사 조건을 수정했고 최종 전체 시나리오가 통과했다. 제품의 잘못된 마감 적용 결함을 수정한 것은 아니다.

## 지원 경계

이번 확인은 지원 문법의 사각형 스케치·선택 윤곽 돌출·선택 솔리드 윗면 중심의 원형 관통 구멍·월드 Z 수직 모서리 필렛이다. 다른 치수의 독립 3D 도구는 기존 도구 범위를 따르며, 임의 자연어 해석·복잡한 2D 건축 도면의 의미 인식과 자동 3D 변환·임의 면/모서리의 대화 지정을 검증했다고 보지 않는다. Local rules로 수행했으며 mock gateway나 실제 모델 provider가 대신 정답 명령을 반환한 검사가 아니다.

이 검증은 원본이 이어지는 생성/마감 경로를 확인했다. 최종 마감 이후 임의의 원본 2D 구속 수정이 모든 면 참조를 항상 유지한다고 보증하지 않는다. 위상이 바뀌어 참조가 모호해지는 경우 기존 unresolved/repair 정책을 적용해야 한다.
