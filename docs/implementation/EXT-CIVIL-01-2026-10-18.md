# 외부 주거 DWG/PDF로 확인한 가져오기 개선

2026-10-18. [Abhishekh-Jha/Civil_projects](https://github.com/Abhishekh-Jha/Civil_projects)의 공개 주거 도면을 주 검증 대상으로 사용했다. 자체 Q1 fixture와 독립된 외부 입력이다. 원본을 그대로 가져오는 호환성 완료 판정이 아니라, 실제 결함을 수정한 첫 검증이다.

## 입력과 비교 조건

- 고정 commit: `5bdb0e47140f8bbbc59d630513971cbb11409cbb`.
- AutoCAD 2024 DWG 1,326,268 bytes와 작성자가 게시한 PDF 195,562 bytes. PDF는 회전된 Letter 한 페이지에 GROUND FLOOR, FIRST FLOOR, FRONT ELEVATION을 배치했다.
- 앱에는 DWG 직접 읽기가 없다. 별도 테스트 도구 LibreDWG 0.14.8612 win64로 ASCII DXF를 변환했다. 변환기는 unstable class 경고를 냈으므로 DWG→DXF 단계가 무손실이라고 주장하지 않는다. 변환 도구는 앱에 내장하지 않았다.
- DXF는 inches, root LINE 554, LWPOLYLINE 107, INSERT 79, HATCH 61, MTEXT 58, DIMENSION 24, CIRCLE 12, ARC 1, VIEWPORT 2다. 원본 전체 블록 정의는 265개다.
- 원본 PDF와 결과 PDF를 각각 Poppler로 렌더링했다. 결과는 기존 프레임 기능으로 A3 420×297mm, 1:150에 재배치한 발행본이다. 종이 크기·축척이 달라 픽셀 동일성을 합격 조건으로 쓰지 않는다.

## 발견한 결함과 수정

1. **방 이름·규격 누락:** MTEXT를 전부 버리고 있었다. content chunks, 문단, Unicode와 기본 문자 방향을 읽어 편집 가능한 텍스트 행으로 가져온다. 서체·자동 줄바꿈·rich formatting·attachment의 정확한 재현은 지원하지 않으며 별도의 변환 동의를 받는다. 열 구성·비정상 좌표·알 수 없는 제어문자·지나치게 큰 내용은 제외한다.
2. **치수 전체 누락:** DIMENSION의 익명 표시 블록을 가져오지 않았다. 원본 display block을 WCS 정적 블록으로 연결한다. 원본 문구·보조선·틱은 유지되지만 연관성·치수 객체 편집 의미는 유지되지 않는다. 표시 블록 누락과 비표준 extrusion은 명시적으로 제외한다.
3. **틱/채움 경계 누락:** 폭 있는 polyline은 중심선으로, SOLID는 DXF 정점 순서에 맞는 닫힌 경계로 가져온다. 폭과 solid fill 손실은 변환 고지에 표시한다. 음수 폭·두께·비정상 geometry는 거부한다.
4. **숨긴 블록 변형이 표시됨:** DXF group 60의 숨김 표시를 무시해 문·나무 등의 비표시 변형까지 겹쳐 그렸다. source-hidden 객체는 가져오기에서 제외하고 같은 원인의 제외 건수를 묶어 표시한다. 숨김 형상을 앱에서 다시 켜는 왕복 복원은 지원하지 않는다. 원본 파일은 보존한다.
5. **불필요한 블록/경고:** 기본 경로는 배치된 블록의 재귀 의존만 정의한다. 실제 45개를 가져온다. 사용하지 않는 블록의 손실은 해당 가져오기의 경고에 섞지 않는다. 준비 옵션의 `usedOnly:false`를 명시하면 기존처럼 미사용 정의까지 유지하므로 PURGE 검증 경로도 보존한다.
6. **신규 객체마다 전체 재생성:** 신규 layer/drawing/text/block과 그 신규 객체의 배치만 추가하는 batch를 엄격하게 구분해 마지막에 한 번 갱신한다. 기존 객체·레이어 수정, 기존 block 삽입, 일반 drafting/모델 수정은 이 경로를 사용하지 않는다. 실패 시 전체 rollback, 단일 Undo/Redo, 마지막 문서 검증을 유지한다.
7. **표시 병목:** 블록 정의의 공통 signature를 화면 갱신당 한 번 계산하고, plain text·미표시 원본에는 불필요한 전체 정의 직렬화를 하지 않는다. 같은 스타일의 블록 실선을 LineSegments2로 묶는다. dashed 경로는 기존 연속 거리 계산을 유지한다. 문서 기하·선택할 객체·출력 데이터는 바꾸지 않는다.

## 검증 결과

첫 실행에서는 root 750개만 가져왔고 MTEXT/치수가 빠졌다. 최종 root는 **848개**, 필요한 블록 **45개**, 내보내기 장면 문자 **98개**다. definition 작업용 hidden source를 포함한 문서 객체는 **2161개**다. root HATCH 61개를 포함한 나머지 손실은 제외 동의를 요구한다. 최종 검증 수치와 실행 조건은 [manifest](../verification/EXT-CIVIL-01-2026-10-18.json)를 따른다.

Node에서는 전체 가져오기→단일 Undo/Redo→WebCAD 직렬화/재열기→SVG 장면을 확인했다. 실제 브라우저에서는 파일 입력·분리된 preview·변환/제외 동의의 분리·가져오기·Undo/Redo·문자 편집·재열기·기존 A3 프레임과 Worker PDF를 검증했다. 문자 편집·프레임 생성·재열기는 기존 명령/파일 API를 사용했다. 모든 작업을 UI로 작성했다고 해석하지 않는다.

초기 비최적화 실행은 수분 동안 완료되지 않아 중단했다. 수정 후 Node의 전체 가져오기는 약 0.45–1.44초를 관측했으나 코드/환경이 함께 바뀌었으므로 같은 조건의 배속 비교를 주장하지 않는다. 브라우저 전체 반영은 소프트웨어 GPU·대량 선택·트리·그리기 비용을 포함해 더 오래 걸린다. 임시 프로필의 native 입력 제한과 큰 산출물 report 제한도 fixture 크기에 맞게 조정했다. 최종 신규 브라우저 13개는 Chrome/SwiftShader에서 통과했다. Edge에서는 큰 fixture의 native 입력 응답 시간 초과가 반복되어 일관된 통과를 확인하지 못했다. 이를 브라우저 전반의 성능 해결로 확대하지 않는다. 전체 Node 1491개/54 suites, 기존 브라우저 회귀 116개, architecture 704모듈과 최종 build를 통과했다.

## 원본 PDF와 남은 차이

해치 패턴/채움, 개체별 색·ByBlock 상속·선종류, 글꼴과 정교한 문자 배치, dynamic block 평가·외부 참조·paper-space/viewport 출력 설정을 완전히 보존하지 않는다. 특히 벽/지붕 채움과 가구·조경 색이 원본 PDF와 다르다. 화면을 읽을 수 있게 복구한 결과를 실무 납품 호환성 완료나 원 설계의 정확성 보증으로 확대하지 않는다. 다음 우선순위는 이 도면에서 실제 확인한 **HATCH와 색/스타일 보존**이다.

## 재실행과 산출물

```powershell
python apps/web/scripts/prepareExternalCivil.py
pnpm --filter @agent-webcad/web exec tsx scripts/auditExternalCivil.ts
pnpm --filter @agent-webcad/web test:browser --page=externalCivil --artifacts
```

입력은 [공개 저장소](https://github.com/Abhishekh-Jha/Civil_projects)에서 고정 commit으로 내려받고 SHA-256을 검사한다. 공개 다운로드와 재배포 라이선스를 같은 것으로 보지 않는다. 원본은 로컬 검증 입력으로 보관하며 앱 자산으로 번들하지 않는다. converter는 `tmp/tools`에 둔다.
