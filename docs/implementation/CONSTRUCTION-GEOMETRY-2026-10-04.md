# 저장되는 점·직선·반직선과 연쇄 작도

> **현재 기능 설명:** [정밀 작도와 편집](../features/DRAWING-EDITING.md). 이 문서는 날짜별 구현·설계 기록이며, 아래 사용법·제한·수치는 당시 범위다. 후속 지원은 대표 가이드를 따른다.

> 단계 기록: 아래 구현·검수 수치는 해당 시점의 근거다. 최신 지원 범위는 [CAD-BASICS](../product/CAD-BASICS.md), 최근 전체 검수는 [PROJECT-STATE](../../PROJECT-STATE.md), 다음 실행 순서는 [NEXT-STEPS](../../NEXT-STEPS.md)를 따른다.

2026-10-04. G1 범위를 기존 CadFeature·Dependency Graph·공용 Preview/Apply에
연결했다. 캔버스와 저장 파일은 같은 객체와 정의를 사용한다.

## 사용 흐름

1. **2D → Draw → Construction**을 연다. Independent point, Independent infinite
   line, Independent ray는 좌표 또는 캔버스 클릭으로 생성한다. U,V는 작업면
   좌표이고 mm/cm/m/in, 상대 `@` 입력을 지원한다. Plane elevation은 작업면
   법선 방향의 높이다. 무한선/반직선의 두 번째 점은 방향을 정하는 통과점이다.
2. 독립 점 A와 B를 만든다. Segment through two points에서 저장된 A,B를
   선택하거나 캔버스에서 집어 AB를 만든다. 기존 Line 도구의 `line`은 유한
   선분이며, 예전 파일도 동일하게 해석한다.
3. Midpoint of segment에서 AB를 골라 M을 만든다. Perpendicular bisector at
   midpoint에서 AB와 M을 골라 무한 수직이등분선 L을 만든다.
4. 원 O를 만든 뒤 Intersection에서 L과 O를 선택한다. Positive/negative
   branch로 P,Q를 따로 만든다. 두 분기는 원 중심을 선에 투영한 위치에서 선의
   방향을 따라 `+/-`인 교점이다. 반직선의 두 교점이 모두 원점 앞에 있어도
   각 분기는 유지된다. Intersection은 기본적으로 최종 도형으로 생성한다.
5. 독립 점 A를 선택하고 **Direct** 핸들을 드래그한다. 수치 입력으로 목표를
   조정할 수 있다. 미리보기에서 AB,M,L,P,Q의 수정 전후 위치와 보존할 작도식을
   함께 확인한다. Apply는 검토한 결과를 한 Undo 단계로 확정한다.
6. 객체의 **Dependencies**에는 저장된 작도식·직접 입력·상위 관계가 보인다.
   파생 좌표를 직접 덮어쓰는 편집은 막고 원본 편집으로 안내한다.
7. **Hide construction / Show construction** 한 번으로 모든 보조 형상의 캔버스
   표시를 전환한다. 숨긴 형상은 캔버스 선택·스냅에서 제외되며, 최종 교점은
   계속 보인다. 도면·구속·관계·프로파일·이력과 출력 설정은 바뀌지 않는다.

## 저장·재계산 계약

- `CadFeature.construction`은 타입 있는 연산과 입력 ID를 저장한다.
  `params.points`는 평가 결과이며 정의를 대신하지 않는다.
- 연산: `segment`, `line-through`, `ray-through`, `midpoint`,
  `perpendicular-bisector`, `intersection`. 독립 `point`, `infinite-line`, `ray`
  는 drawing 피처로 저장한다. 별도의 노드/AI 전용 기하 원본을 만들지 않았다.
- 입력 변경은 기존 피처 재생성 순서에서 전파된다. 점 핸들, 이동/변환,
  원 반지름 핸들 변경으로 작도가 갱신된다. 객체·위상 ID와 교점 분기를 보존한다.
- 접점에서는 P,Q가 같은 좌표를 가지되 두 객체와 분기가 유지된다. 원본 수정으로
  다시 두 교점이 생기면 기존 분기로 돌아간다. 선–선 교점은 하나이며 선분/무한선/
  반직선의 실제 도메인을 적용한다. 평행/일치한 선은 유일한 교점이 없으므로 거절한다.
- 교점 소실, 선분 붕괴, 서로 다른 작업면/높이, 비원형 스케일, 필요한 원본 삭제는
  수정 전체를 거절한다. 일부 파생점이나 이력만 남지 않는다. 관련 객체를 삭제할
  때에는 하위 결과부터 제거한 후 원본을 삭제한다.
- 새 정의/객체가 있는 문서는 **WebCAD schema v4**로 저장한다. 기존 v1–v3
  파일의 선분 의미는 유지한다. 버전 위조, 누락된 원본, 순환 관계, 잘못된 평가
  캐시는 열기/복구 시 진단하며 현재 문서에 적용하지 않는다. 일반 package
  deserialize는 구조를 검사하고, 앱의 파일 열기/복구 경로는 평가 캐시까지 검사한다.
- Query는 실제 ID와 분기를 읽기 전용으로 반환한다. 캔버스/Inspector 작도식은
  사람이 붙인 객체 이름으로 표시한다. 이름 변경은 관계 ID에 영향을 주지 않는다.

## 렌더·정밀도

- 무한선/반직선은 카메라 프러스텀에서만 표시 범위를 잘라 낸다. 길이를 매우 큰
  수로 저장하지 않는다. Fit은 원점/통과점의 작성 범위를 사용해 무한히 확대되지
  않는다. Window 선택은 유한 창에 전체가 들어오지 않는 무한 형상을 제외하고,
  Crossing 선택과 클릭은 표시된 실제 선의 범위를 사용한다.
- 점 표시는 화면 픽셀 크기를 유지하고 클릭 판정도 픽셀 기준이다. 반직선 뒤쪽은
  선택/교점/Nearest 스냅 대상이 아니다. 무한선 통과점을 가짜 끝점으로 스냅하지 않는다.
- 교점 계산은 큰 좌표의 제곱을 빼는 대신 원 중심의 투영과 상대 거리로 계산한다.
  XY/XZ/YZ, 17 mm 높이, 1e8 mm 부근 좌표를 검수했다.
- 화면 갱신은 기존 GPU 버퍼를 재사용한다. 고정 카메라에서 매 프레임 버퍼를
  교체·업로드하지 않으며 표시용 클리핑은 저장 좌표나 해석적 측정을 바꾸지 않는다.

## 검수와 현재 경계

추가 Node 회귀 검사 13개: 명령·분기·실패 원자성·스키마·작업면/큰 좌표·스냅
도메인·GPU 버퍼·프로파일/출력 구분. 실제 브라우저 검사 25개: 단위/상대 입력,
원본 캔버스 선택, 작성된 무한선/반직선의 범위 선택, 작도 생성, 점 드래그와
정밀 미리보기, 한 Apply/Undo/Redo, 보조 형상 숨김, 최종점 선택, 설명/Query,
저장·재열기 후 재계산과 실패 거절.

전체 검수는 Node **461개 / 49 suites**, 브라우저 **17과제 / 343개 검사**,
production 빌드로 기록한다. 로그: `tmp/construction-full-node.log`,
`tmp/construction-full-browser.log`, `tmp/construction-full-build.log`.
캔버스 검수 이미지: `output/images/cad-construction-preview.png`,
`output/images/cad-construction-cascade.png`. 기존 큰 chunk 경고는 남아 있다.

현재 작도 교점은 직선 계열–원, 직선 계열–직선 계열이다. 원–원, 호/일반 곡선
교점, 접선 작도, 각 이등분선, 외접원/내접원, Locus와 노드 UI는 후속 과제다.
저장된 작도 **입력 정의의 재지정 UI**는 아직 없으며 원본 편집으로 재계산한다.
독립 점/무한선/반직선은 아직 스케치 솔버 엔티티가 아니다. 작도 그래프와 동시
구속 해석의 역할을 구분한다. 일반 선분은 기존 스케치/돌출 기반을 유지한다.

새 객체/작도 원본의 완전 보존 포맷은 WebCAD JSON이다. 기존 DXF 출력에서는
새 Point/XLINE/RAY를 건너뛰고 skipped 수에 포함한다. SVG/PDF의 유한 도면
출력도 새 객체를 제외한다. 짧은 방향 정의를 유한 선분으로 잘못 출력하지 않는다.
전문 포맷 변환과 명시적 출력 창에 따른 무한 형상 클리핑은 후속 어댑터 과제다.
