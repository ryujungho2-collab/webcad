# ARC 1.7 무선 전기주전자 · 2D/3D 검증 과제 (2026-11-05, Claude)

산업디자인 졸업작품 수준 과제로, 실제 CAD 명령과 OCCT 커널만 써서 만들고 검증했다. 커밋하지 않았다. 아직 미완성이다(아래 "남은 일").

- 빌드: `apps/web/scripts/arcKettle/buildModel.ts` (약 130초)
- 검증·도면·출력: `apps/web/scripts/arcKettle/verify.ts` (약 6분)
- 결과: `output/projects/arc-kettle/` — `arc-kettle.webcad.json`, `ga.svg`/`ga.dxf`(A2 1:2), `arc-kettle.step`, `arc-kettle.glb`, `verification.json`

## 설계

- 몸통: 원형 단면 6개(2D)를 매끄럽게 로프트하고, 바닥에 R10 필렛, 벽 1.8 mm 쉘.
- 주둥이: 닫힌 스플라인 단면을 로프트해 몸통과 합치고, 안쪽 통로를 파낸 뒤 z=203에서 수평으로 잘라 따르는 입구를 만들었다.
- 손잡이: D형. 2D 스파인을 따라 스윕하고, 몸통 외피에 정확히 맞게 잘랐다. 로커 스위치 포켓이 있다.
- 수위창(Tritan): 몸통 벽과 같은 곡면.
- 뚜껑: 돔에 스커트, 속이 비어 있고 스틸 노브.
- 히터 하우징: 360° 커넥터 홈.
- 전원 베이스: 속이 비어 있고 커넥터 보스와 케이블 홈.
- 부품 9개마다 재질과 색을 지정했다.

## 검증 결과 (44/45 통과)

- **3D:** 9개 부품 모두 BRep 유효. 껍데기 질량 약 566 g.
- **용량:** 정확한 내부 솔리드를 높이별로 잘라 계산했다. 끝까지 채우면 2.129 L이다. 1.700 L가 차는 MAX선은 139.1 mm, 0.502 L의 MIN선은 38.4 mm다. MAX선에서 끓음 여유는 55.9 mm, 따르는 입구는 MAX선보다 63.9 mm 위에 있다. 수위창은 MIN과 MAX를 모두 덮는다.
- **조립:** 맞닿는 부품 쌍 9개의 BRep 거리를 쟀다. 겹침은 0이다.
  - 뚜껑 슬라이딩 틈새 0.599 mm
  - 커넥터 1.5 mm
  - 베이스 안착 0.5 mm
  - 나머지는 접촉
- **사용성:** 손잡이 그립 168 mm, 손가락 마디 여유 48 mm, 베이스 반경 78.8 mm가 몸통보다 크다(작업대에서 안정). 전체 높이 247 mm.
- **2D↔3D:**
  - 2D 뚜껑 단면 원을 바꾸면 3D 뚜껑이, 2D 손잡이 스파인 제어점을 바꾸면 스윕부터 손잡이까지 다시 생성된다. Undo는 정확히 되돌린다.
  - 정면도 폭은 3D와 0.05 mm 이내, 높이는 일치한다.
- **2D 도면:** HLR 정면 253, 측면 337, 평면 240개 요소. 단면 A-A는 절단선 87개, 해칭 107개. A2 1:2 시트를 SVG와 DXF(누락 0)로 출력했다.
- **교환:** STEP을 새 리더로 다시 읽으면 9/9 유효. GLB 1.39 MB. 저장한 뒤 다시 열어도 도면이 resolved 상태다.
- **실패 1개:** STEP을 다시 읽은 체적 편차가 최대 0.26%로, 기준 0.2%를 넘는다. 어느 부품인지는 아직 확인하지 않았다(자유곡면 부품으로 추정).

## 과제 중 고친 플랫폼 문제 (원본 반영)

1. **큰 곡면 솔리드에서 쉘·면 지정 측정이 안 됨**(제 10-31 변경의 회귀)
   - 증상: 크기 비례 테셀레이션 때문에 면 하나만 다시 메시하면 면 키가 전체 솔리드에서 만든 키와 달라진다.
   - 수정: `shapeToMesh(shape, deflection?)`를 추가했다. `shell.ts`와 `selectedDistance.ts`가 부모 솔리드의 deflection으로 면 키를 맞춘다.
2. **로프트·스윕 부품은 투영도와 단면을 만들 수 없음**
   - 증상: 윤곽선과 단면선이 9~14차 BSpline이라 "Kernel spline exceeds support budget"로 거부됐다.
   - 수정: `spline.ts`에서 8차 이하로 다시 근사한다. OCCT가 최대 편차 1 µm 이하(`SPLINE_REFIT_TOLERANCE`)를 보증할 때만 받아들이고, 넘으면 지금처럼 거부한다.
3. **대칭 부품의 정면 투영 실패**
   - 증상: 앞뒤 윤곽선이 2D에서 완전히 겹쳐 "Ambiguous coincident section edges"로 실패했다.
   - 수정: `modelSection.ts`에서 서술자와 종류가 같은 중복을 하나만 남긴다. 예전에는 거부되던 경우라 저장된 출력 ID에는 영향이 없다.
- 회귀 테스트: `tests/freeformDrawing.test.ts`를 추가했다(6단면 로프트의 세 방향 투영과 단면이 resolved). 관련 테스트 86개, tsc, 아키텍처 검사 모두 통과. 전체 Node·브라우저 스위트는 이번에 다시 돌리지 않았다.

## 남은 일

- STEP 체적 편차 0.26% 원인 부품 확인.
- `layout-model-sheet-set` 자동 배치는 모든 출력이 보이는데도 "Show all selected view outputs"로 거부됐다. 원인 미조사. 그래서 `upsert-model-sheet`로 위치를 직접 지정했다(배치 좌표는 월드 좌표).
- 시트에는 아직 치수와 표제란이 없다. 시트 SVG 화면도 눈으로 확인하지 않았다.
- 렌더 이미지와 발표 보드 미작성. 실제 앱 화면에서 형태는 확인했다.
- 테스트 실행이 `output/verification` 보고서를 다시 쓸 수 있다.
