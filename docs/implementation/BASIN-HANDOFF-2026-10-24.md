# 비정형 세면 볼 · 혼합 윤곽과 배수구 인계

2026-10-24. CAD 원본·STEP·도면 (local-only, not in repository: `output/projects/organic-basin/README.md`).

약 700 mm급 비정형 세면 볼과 분리형 배수 부품으로, 닫힌 NURBS와 원을 함께 선택하는 실제 작업을 검증한다. 사람은 외곽 곡선과 배수구 원을 만들고, 공통 돌출 폼과 내부 자연어로 구멍이 있는 바닥을 작성한다. 실제 MCP는 내부 곡선, 배수구 자리, 솔리드 결합, 별도 배수 부품과 연관 단면을 이어서 작성한다. 후속 내부 곡선 수정도 사람·자연어·MCP의 동일 도구를 사용한다.

기존에 별도 솔리드 연산을 요구하던 닫힌 spline 경계와 analytic 경계의 조합을 native 프로파일 추출에 연결했다. 원래 NURBS·원·선·원호는 그대로 유지한다. 기존 positive rational Bezier 경계 검증과 root isolation으로 교차·접촉·포함 관계를 확인하고, 포함 깊이에 따라 구멍과 독립 섬을 구분한다. 스플라인의 방향을 작업 평면 normal에 맞춰 정규화하므로 선택 순서나 원본의 시계/반시계 방향이 구멍을 메우지 않는다. 혼합 외곽의 순면적과 둘레도 각 경계의 실제 곡선 적분으로 계산한다. 하나의 열린 스플라인과 선을 연결해 경계로 만드는 기능은 이번 범위가 아니다.

공통 돌출 폼은 영역 수·구멍 수·외곽/구멍의 실제 source IDs·순면적을 표시한다. `cad.context`도 현재 선택이 윤곽일 때 같은 분류기의 `profile` 읽기 결과를 제공한다. 이 추가 읽기는 선택이나 문서를 바꾸지 않는다. 구멍의 역할을 에이전트가 선택 순서로 추측할 필요가 없다. canonical 도구 39종, MCP 노출 42종, 사람용 공통 폼 12종은 유지한다. native 돌출이 거절될 때는 실제 윤곽 오류를 전달한다.

저장 형식 51은 구멍을 가진 스플라인 프로파일을 식별한다. 중첩 Boolean 피연산자와 planar face region도 검사하며 이전 버전으로 위장한 파일은 거절한다. 기존 구멍 없는 spline 파일은 계속 형식 50을 사용한다.

세면 볼 바닥은 18 mm, 벽 높이는 160 mm다. 내부 곡선은 외곽을 0.93배 한 형상에서 시작하므로 벽 두께가 일정한 shell은 아니다. 배수구 반지름은 22.5 mm이며 Z12–18의 자리 반지름은 26.5 mm다. 별도 배수 부품은 외경 Ø44/Ø52, 내경 Ø38로 작성해 각 자리에서 반지름 방향 여유 0.5 mm를 남긴다. 실제 BRep 절단에서 동심원 반지름을 확인한다. 바닥 경사·방수 씰·설비 규격·제조 공차 검증은 하지 않는다.

내부 곡선을 외곽 밖으로 이동하는 제안은 연결된 ring/Boolean을 재생성하는 도중 전체가 거절된다. 유효한 수정은 같은 트랜잭션에서 3D를 재생성한다. 단면 대응을 증명할 수 없으면 이전 출력을 숨기고, 기존 `drawing.refresh` 폼에서 명시적으로 재연결한다. 실제 브라우저·공식 SDK MCP, 독립 체적 공식, Undo와 저장 후 재열기 검증 결과는 [검증 기록](../verification/BASIN-HANDOFF-2026-10-24.json)에 남긴다.


이번 실제 과제에서 복잡한 live Boolean과 연관 단면을 다시 검증하는 MCP 호출이 기존 요청 제한 시간을 넘는 연결 결함도 발견했다. `cad.propose`의 선택 인자 `waitForReview:false`는 즉시 `validating` 접수 번호를 반환한다. `cad.proposal`로 상태를 조회해 `pending-review`를 확인한 뒤 사람이 기존 CAD 화면에서 Apply한다. 기존 동기 호출은 유지한다. 비동기 native 검증은 180초로 제한하며 문맥 변경·연결 해제·실패를 `cancelled` 또는 `rejected`로 확인할 수 있다. 접수 번호가 반환됐다고 도면이 게시된 것은 아니다. 이 방식은 미리보기 연산을 빠르게 만드는 기능이 아니라, 긴 검증 때문에 MCP 연결이 끊기는 문제를 분리하는 기능이다.

실제 UI/Worker/공식 SDK stdio 검증 47개, 관련 단위·통합 검증 96개를 통과했다. 기존 키오스크 48 / 손잡이 42 / 브래킷 인계 38 / MCP bridge 24 / 고급 도구 17개도 통과했다. production build는 기존 chunk 크기 경고만 남긴다. 비동기 검증 완료 후에는 캡처한 CAD 세션을 해제하고 작은 접수 메타데이터만 유지한다.
