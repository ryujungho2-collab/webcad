# CAD 기능 구현 + 온톨로지 동반 갱신 실행 가이드

작성일: 2026-11-06. GPT-6.1 Sol / Medium 작업용 인계 지시서.

이 문서는 구현 지시서다. 아래 예정 기능을 구현 완료로 표시하지 않는다. 한 세션에서는 지정된 작업 카드 하나만 구현한다.

## 1. 목표와 현재 기준선

CAD 기능을 작은 단위로 완성하고, 그 기능의 실제 대상·지원 범위·실행 경로·검증 근거를 기존 Capability Ontology에 함께 반영한다. 이후 2D/3D 관계 조회 및 외부 물리 해석으로 확장할 기반을 남긴다.

- 출발 체크포인트: `7f6e26a`, `codex/checkpoint-2026-11-06`.
- 실행 시 실제 HEAD와 변경 사항을 다시 확인한다. 이후 작업을 위 커밋으로 되돌리지 않는다.
- 체크포인트에서는 웹 빌드와 아키텍처 검사만 새로 통과했다. 전체 unit/browser suite의 현재 통과를 의미하지 않는다.
- 120개 대응표는 같은 조작 16 / 다른 조작 50 / 부분 31 / 미확인 23의 **2026-11-05 감사 기록**이다. 미확인을 결함 또는 미구현으로 단정하지 않는다.
- 기존 Capability Ontology는 `apps/web/src/ontology/capabilities/`에 구현돼 있다. 새 카탈로그·분류 엔진을 중복 생성하지 않는다.
- NVIDIA Auto Ontology, DB, 외부 해석 엔진, 새 LLM 공급자 연결은 이번 작업 범위에서 제외한다.

## 2. 시작 절차

1. 적용 가능한 `AGENTS.md`와 현재 `git status`, branch, HEAD를 확인한다.
2. 관련 기존 코드와 테스트를 먼저 읽는다. 오래된 문서보다 실제 구현을 우선한다.
3. 같은 기능이 이미 구현돼 있으면 중복 구현하지 않는다. 실제 부족한 경로만 좁힌다.
4. 5~10줄로 구현 범위·상태 소유자·수정 예상 파일·검증 명령을 알린 뒤 진행한다. 이미 승인된 범위의 일상적 구현 선택마다 재승인을 요구하지 않는다.
5. 새 작업 브랜치는 `codex/` 접두사를 사용한다. 다른 작업의 변경을 reset/clean/stash하거나 덮어쓰지 않는다. 중첩 수정이 발견되면 범위를 분리한다.

## 3. 모든 기능의 완료 계약

| 구분 | 완료에 필요한 증거 |
| --- | --- |
| 제품 동작 | 실제 UI에서 진입하고 지원 입력으로 작업을 완료할 수 있음 |
| 상태 변경 | 문서 편집이면 기존 검증·트랜잭션·History를 통과. 화면 전용이면 문서 불변을 검증 |
| 실패 처리 | 잘못된 입력·삭제된 참조·취소에서 부분 변경이 남지 않음 |
| 참조 | 기존 ID·소유 관계를 보존. 대응을 모르면 재연결을 추측하지 않음 |
| 저장 | 문서 데이터의 변경은 기존 직렬화·재로드 계약에 따름. 화면 상태를 임의로 문서에 추가하지 않음 |
| 온톨로지 | 실제 기능 ID·대상·executor·UI·제한·근거를 갱신. 명령 후보 조회가 실행 허가를 대신하지 않음 |
| 검증 보고 | 이번 실행, 과거 기록, 실패, 미실행을 구분 |

### 문서 편집과 화면 동작을 구분한다

- 기하·치수·스타일·저장되는 객체/레이어 값을 바꾸면 기존 CommandBus와 검증 가능한 트랜잭션을 사용한다.
- 기존 작업이 Review/Apply라면 그 흐름을 재사용한다. 모든 가벼운 UI 동작에 새 승인 모달을 만들지 않는다.
- 화면 필터·패널 열기처럼 문서를 바꾸지 않는 동작은 기존 UI 상태 경로를 따른다. 이를 위해 가짜 CAD 명령이나 Undo 항목을 만들지 않는다.
- 실제 형상과 무관한 기능에 새 BRep 연산·solver·문서 버전을 추가하지 않는다.

## 4. 첫 작업 카드 — CAD-LAYER-01

### 목표

선택 객체가 속한 레이어를 임시로 격리하고 해제할 수 있게 한다. 대응표 097/098의 사용자 작업을 지원한다. 레이어 동결·전체 켜기·특성 복사 등은 다음 카드로 남긴다.

### 반드시 재사용할 코드

저장소 루트 기준 경로다. 줄 번호는 변경될 수 있으므로 심벌로 찾는다.

- `apps/web/src/App.tsx`: `isolatedObjectIds`, `handleIsolateObject`, `handleShowAllObjects`, 프로젝트/문서 전환 정리
- `apps/web/src/viewport/CadViewport.tsx`: `isolatedObjectIds`를 사용하는 렌더·hit test·선택 경로
- `apps/web/src/explorer/views/LayersPanel.tsx`: 기존 레이어 UI와 가시성·잠금 동작
- `apps/web/src/commands/paletteCommands.ts`: 기존 `isolate`, `show-all` 등록
- `apps/web/src/state/documentSession.ts`: 문서 identity / generation / revision
- `apps/web/src/ontology/capabilities/records.ts`: `layer-isolate`, `isolate-selection`
- `apps/web/src/ontology/capabilities/index.ts`: 기존 조회 및 `capabilityInventory`
- `apps/web/tests/draftingVisibility.browser.tsx`: 기존 실제 입력·가시성 검사 패턴
- `apps/web/tests/ontologyCapabilities.test.ts`: 실제 계약 및 감사 매핑 검증

### 상태 정책 — 이번 카드에서 확정한다

**기존 객체 격리처럼 viewport-only 필터로 구현한다.** 레이어의 `visible`·`locked`나 객체 `visible`을 임시로 덮어쓰지 않는다.

| 상황 | 정책 |
| --- | --- |
| 선택 없음 | 실행 불가 이유 표시, 상태 변화 없음 |
| 여러 객체 선택 | 유효 객체의 layer ID를 중복 제거하여 격리 대상에 포함 |
| 숨겨진 객체/레이어 | 기존 숨김을 강제로 해제하지 않음 |
| 잠긴 레이어 | 기존 표시·선택·편집 정책을 그대로 유지. 격리가 잠금을 해제하지 않음 |
| 레이어 격리 해제 | 필터만 제거. 별도 문서 편집이 없었다면 격리 전 표시와 정확히 동일 |
| 격리 중 명시적 가시성 편집 | 기존 명령으로 처리. 해제 때 그 편집을 과거 스냅샷으로 되돌리지 않음 |
| 객체 격리와 레이어 격리 | 중첩하지 않음. 다른 모드를 시작하면 이전 필터를 교체하고 UI에 현재 모드를 표시 |
| 같은 격리 동작 반복 | 활성 모드에서 해제하는 동작으로 일관되게 제공 |
| 격리 중 새 객체 | 대상 레이어에 추가되면 기존 가시성 정책 아래 표시, 다른 레이어면 필터링 |
| 격리 중 새 레이어 | 대상 집합에 자동 추가하지 않음 |
| 격리 대상 레이어 삭제 | 존재하는 대상만 사용. 모두 사라지면 격리 종료. 삭제된 레이어를 복구 생성하지 않음 |
| 문서 열기/새 문서/프로젝트 전환 | 이전 격리 상태 초기화. 같은 object/layer ID의 다른 문서에 누출 금지 |
| Undo/Redo | 격리 자체는 History를 만들지 않음. 실제 문서 편집의 Undo/Redo는 기존 동작 유지, 필터는 유효 ID 기준으로 갱신 |
| 파일 저장·재로드 | 격리 필터는 저장하지 않음. 문서의 원래 가시성·잠금은 저장/복원. 재로드 시 격리 없음 |
| 출력 | 화면 임시 격리는 기존 문서 기반 출력 결과를 변경하지 않음. 기존 출력 가시성 정책 유지 |

렌더링에서만 감추고 hit test나 박스 선택에서는 선택되는 상태를 만들지 않는다. 캔버스에서 보이지 않는 요소의 직접 편집 핸들도 노출하지 않는다. Explorer의 기존 전체 목록 정책을 임의로 바꾸지는 않는다.

현재 viewport에 전달하는 객체 필터를 레이어 ID에서 파생하는 방안을 먼저 검토한다. 매 렌더마다 전체 그래프를 새로 만들지 말고 기존 revision 갱신 패턴을 활용한다. 별도 Scene Graph나 visibility 엔진은 만들지 않는다.

### UI 범위

- 기존 Layers 패널에 선택 객체 레이어 격리와 해제 경로를 제공한다.
- 기존 명령 팔레트에서도 검색·실행할 수 있게 연결한다.
- 현재 격리 모드를 사용자가 확인할 수 있게 한다.
- 기존 객체 격리·Show all objects 동작을 삭제하거나 다른 의미로 바꾸지 않는다. Show all 실행 시 새 필터의 정리도 확인한다.
- 새 기본 단축키, 명령행, MCP 도구는 이번 카드에 추가하지 않는다.

### 수정 경계

App / LayersPanel / palette 및 필요한 props 연결, 작은 순수 필터 helper, 관련 테스트와 온톨로지·문서를 우선한다. 기존 CadViewport 필터로 해결된다면 렌더러를 다시 구현하지 않는다.

문서 스키마·직렬화 버전·커널·solver·Copilot 실행기 변경이 필요하다고 판단되면 먼저 이유를 기록하고 이번 정책으로 해결 가능한지 재검토한다. 그 범위로 자연스럽게 확장하지 않는다.

## 5. 첫 카드의 온톨로지 동반 갱신

- 새 기능 ID를 만들지 않고 기존 `layer-isolate`를 갱신한다.
- 실제 구현된 UI 동작에 맞게 `kind: interaction`, `executor: ui-state`를 사용한다.
- 새 CAD 명령이나 MCP 도구를 만들지 않았다면 `commandTypes` / `mcpTools`를 채우지 않는다.
- 기존 타입으로 대상 레이어와 선택 집합을 표현한다.
- UI의 실제 palette ID, 빈 선택 조건, 기존 숨김 존중, 임시 필터·비저장·비History 정책, 소스 심벌을 기록한다.
- `supported`는 위 제한 범위에서의 실제 실행 경로를 뜻한다. AutoCAD 모든 옵션 호환을 뜻하지 않는다. UI가 미완성이면 `partial`로 보고한다.
- `capabilityInventory()`에서 JSON을 생성한다. JSON 숫자와 상태를 손으로 따로 고치지 않는다.
- 모델 학습·임베딩·NVIDIA 연결 없이 제품 기능과 설명용 조회가 동작해야 한다.

### 과거 감사와 현재 기능 상태의 충돌

현재 `ontologyCapabilities.test.ts`에는 과거 `unconfirmed` 행이 현재 capability도 반드시 `unconfirmed`여야 한다는 검사가 있다. 기능을 구현하면 이 전제는 달라진다.

2026-11-05 감사 표·매핑·합계는 날짜가 있는 기준선으로 보존한다. 현재 capability의 상태를 갱신하면서, 이번 작업의 날짜·기능 ID·구현 근거·검증 결과를 명시적으로 연결한다. 기존 검사에서 이력과 현재 상태를 구분하도록 최소 수정하고 다음을 모두 검사한다.

1. 과거 120개 매핑과 16/50/31/23 합계는 원문과 계속 일치한다.
2. 과거 미확인에서 승격된 항목은 이번 카드의 097/098과 해당 `layer-isolate`에 한정된다.
3. 승격에는 실제 UI 경로·소스 심벌과 이번 검증 근거가 존재한다.
4. 변경하지 않은 미확인 항목은 계속 미확인이다.
5. 현재 조회와 생성 JSON은 동일하고, 과거 단축키 합계임을 설명한다.

기존 assertion을 삭제하거나 모든 승격을 허용하는 방식으로 통과시키지 않는다. 이력 관리를 위해 별도 범용 카탈로그 시스템을 만들지도 않는다. 필요하면 작은 날짜별 변경 기록을 추가하고 위 조건을 명시적으로 검증한다.

## 6. 검증 예산과 사례

목표는 30~45분의 작은 구현 세션이다. 시간만 맞추기 위해 미검증 기능을 완료로 표시하지 않는다. 원인 불명의 같은 실패는 원인을 좁힌 뒤 최대 2회 재시도하고, 계속 실패하면 근거와 남은 작업을 보고한다.

### 필수 집중 검사

작은 자체 fixture를 사용한다. 3개 이상 레이어, 다른 레이어의 객체, 원래 숨긴 객체/레이어, 잠긴 레이어를 포함한다.

1. 한 레이어와 여러 레이어 격리, 해제 후 표시 복원.
2. 빈 선택과 삭제된 ID 처리, 대상 레이어 삭제/전체 삭제.
3. 객체의 레이어 이동 및 새 객체/레이어 추가 시 필터 갱신.
4. 격리 자체는 직렬화된 문서·revision·History를 변경하지 않음.
5. 격리 중 실제 문서 편집과 Undo/Redo, 해제 후 편집 내용 유지.
6. 문서/프로젝트 전환과 재로드에서 상태 누출 없음.
7. 숨겨진 객체의 raycast·박스 선택·편집 핸들 차단. 기존 잠금 정책 유지.
8. 기존 객체 격리·Show all 회귀, 임시 필터가 출력 데이터를 변경하지 않음.
9. ontology 현재 상태·실제 UI 계약·과거 감사 구분·JSON 일치.

unit/integration은 경계 상태·문서 불변성·계약을 검사한다. 브라우저는 실제 레이어 격리 진입, 표시/선택, 해제, 저장/재로드의 대표 흐름을 검사한다. 내부 함수 호출만으로 UI 검증을 대체하지 않는다.

### 실행 명령 예시

다음 이름은 새 테스트를 만들었을 때의 제안이다. 실제 파일과 러너 등록을 확인한 뒤 실행한다.

```powershell
pnpm --filter @agent-webcad/web exec tsx --test tests/layerIsolation.test.ts tests/ontologyCapabilities.test.ts
pnpm --filter @agent-webcad/web exec node scripts/browserChecks.mjs --page=layerIsolation
pnpm --filter @agent-webcad/web check:architecture
pnpm --filter @agent-webcad/web build
```

- 브라우저 러너의 기존 페이지 선택 옵션을 확인한다. 새 페이지는 한 번만 등록한다.
- 기존 격리 경로를 수정했으면 해당 회귀 페이지를 최대 한 개 추가한다. 예: `draftingVisibility`의 실제 검사 범위를 먼저 확인.
- 최종 빌드·아키텍처 검사는 각 한 번을 기본으로 한다. 실패 후 실제 수정이 있을 때만 직접 관련 검사를 재실행한다.
- 전체 unit suite, 전체 browser audit, 모델 호출, 의존성 설치, 대규모 벤치마크는 이번 범위에 넣지 않는다.
- 브라우저 실행이 불가능하면 사유와 미실행 범위를 남기고 브라우저 완료를 선언하지 않는다.
- 로그는 `tmp/`에 보관한다. 필요한 최종 결과·대표 이미지 한두 장만 선별한다. 외부 도면 fixture를 다운로드하지 않는다.
