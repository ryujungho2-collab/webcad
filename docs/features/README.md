## 공통 편집 규칙

Review/Preview는 변경을 검토하는 단계이며 Apply가 문서에 확정한다. 입력·대상·문서가 바뀌면 이전 Review는 다시 만들어야 한다. 취소한 초안은 History에 추가하지 않는다. 잠긴 대상/종속 결과나 해결되지 않은 참조는 적용 전에 확인한다. 객체 삭제·참조 소멸을 가까운 다른 객체로 조용히 대체하지 않는다. 각 도구의 지원 대상은 대표 문서의 제한을 따른다.

표시 치수·측정값과 모델을 바꾸는 구동 치수는 다르다. 모델 mm와 종이 mm도 구분한다. 저장/재열기의 Undo 경계는 [프로젝트와 저장](PROJECTS.md), 종이 축척/출력 손실은 [도면과 출력](DRAWINGS-OUTPUT.md)이 소유한다.

## 설명을 한곳에 유지하는 방법

- **현재 사용법·지원/미지원:** 이 폴더의 해당 대표 문서 한 곳에서 수정한다. 다른 가이드의 기능은 절차를 복사하지 않고 링크한다.
- **제품 계획:** 앞으로 구현할 동작·선행·완료 조건만 관리한다. 완료한 기능 설명은 대표 문서로 연결한다.
- **진행 상황/실행 큐:** 상태와 우선순위만 요약한다. 사용법이나 한도 표를 다시 만들지 않는다.
- **날짜별 구현/검증:** 당시 동작·설계 이유·수치·실패를 증거로 보존한다. 대표 문서가 최신 설명이며 과거 제한은 후속 기록과 함께 읽는다.
- 새 기능은 해당 가이드에 통합하고 근거를 연결한다. 독립적인 사용자 작업과 갱신 책임이 있을 때만 대표 문서를 나눈다.

설계·코드 위치는 [개발 가이드](../architecture/CHANGE-GUIDE.md), 상세 근거는 [구현 기록 색인](../implementation/README.md)과 [검증 기록 색인](../verification/README.md)에서 찾는다. [이번 통합 범위와 보존 검증](../reviews/FEATURE-DOCUMENTATION-CONSOLIDATION-2026-10-17.md).
