## 제품 방향

정밀한 CAD 기하와 구속을 유지하면서, 그리기·직접 편집·반복 작업·파라메트릭 설계를 편하게 연결하는 통합 제작 엔진을 만든다. 기계 설계와 건축 도면의 작업을 각각 끝낼 수 있어야 하며, 같은 엔진에서 아트보드·벡터·컴포넌트·애니메이션·와이어프레임·프레젠테이션·Copilot/LLM을 사용한다. 기능 확장은 대상·입력값·미리보기·결과 인계를 이어 주는 경험으로 평가한다. 기존 CAD와의 전체 기능 동등성을 달성한 상태는 아니다.

## 구현 구조와 변경 계약

- `packages/cad-document`가 문서·관계·직렬화를, `cad-commands`가 공개 명령·검증·결과를 소유한다. 커널 작업은 `cad-kernel`과 웹의 Worker 서비스로 실행한다.
- 도면 편집은 `apps/web/src/features/drawing-editing/{geometry,commands,ui}`에 모았다. `contracts.ts`는 타입, `registerCommands.ts`는 등록 진입점이다. 공용 변환 함수는 `precision`, 치수 명령은 별도 어댑터에 있다.
- UI·노드·AI는 같은 문서와 명령을 사용한다. Preview는 분리된 제안을 계산하고, Apply는 검토한 제안을 한 Undo로 게시한다. 오래된 계획·잠금·구속·연관 재생성 실패는 부분 변경을 남기지 않는다. 현재 viewport는 WebGL, 기하·메시 계산은 Worker와 제한된 세션 캐시를 사용한다. WebGPU backend, 영속 파생 캐시와 자원 예산은 [웹 런타임 자원 전략](../architecture/WEB-RUNTIME-RESOURCE-STRATEGY.md)에 정의된 다음 작업이다.
- 해석 곡선/BRep 원본과 표시용 mesh를 구분한다. Offset·두 객체 코너·Trim/Join 결과는 적용 당시의 편집 가능한 기하다. 변경되지 않은 해석 모서리 ID와 명시적으로 지정한 치수·솔리드 참조를 보존한다. 영구 Fillet/Trim 정의를 추가한 것은 아니다.
- JSON은 필요한 의미에 따라 v1–v14를 사용한다. 변수/바인딩 v2, live 패턴 v3, 작도 v4, 확장 구속 v5, topology/span 관계 v6, 아트보드 v7, image v8, ellipse mask v9, opacity v10, color adjustment v11, Scene v12, 일반 지름 주석 v13, 일반 각도 주석 v14다. 이전 버전을 읽고 새 의미가 없는 문서는 기존 최소 버전으로 저장한다. 구형 version에 새 주석 의미를 넣은 파일은 거부한다.

`interactionRelations`는 runner에 등록되어 실제 검색→대상 선택→Trim→잘못된 참조/오류→복구→Apply→Join→Edit Sketch와 치수 변경을 실행한다. 검토된 입력을 바꾸면 이전 Apply가 막히며, active sketch/잠긴 레이어의 우클릭 Workflow는 다음 해결 행동을 안내한다. 기존 Pattern 검사 22개는 실제 pointer hit-test로 Fit/Apply/Cancel을 검증한다. 감사와 남은 UX 경계는 [interaction audit](../reviews/INTERACTION-AUDIT-2026-10-04.md)을 따른다. `tmp/trim-final-*`의 519 Node / 20 browser / 411검사는 이전 기준이다.

같은 Node fixture(배경 1,000개 + 패턴 127개, 9회)에서 경로 조회 p95 78.931→1.565 ms, preview 117.457→43.925 ms, Apply 28.781→23.600 ms였다. before/after feature index와 private path cache를 재사용하며 외부 반환값은 복제한다. [측정표](../verification/INTERACTION-PERFORMANCE-2026-10-04.md)는 전체 수치와 한계를 기록한다. 이 측정은 browser input-to-paint나 실무자의 작업 시간 평가가 아니다.

10-04 전체 기준선은 Node 535/49 suites, browser 21과제/429검사, architecture 243모듈이었다. 그 기록은 `tmp/ux-final-*`에 보존하며 G0 결과와 구분한다. 기존 관계 Node 12개·browser 17개는 G0 전체 회귀에도 포함한다.

남은 구조 과제는 App/Viewport session·input lifetime, 구조화된 오류 대상 연결, precision widget 전체 전환, 테스트 전체 별도 typecheck, vector path/import·component override/variant이다. 이미지/PNG/PDF latency는 작은 fixture 단일 관측이며 p50/p95·대형 source/document·retained heap·실무자 작업 시간·reference color-management의 증거가 아니다. output memory 값은 보수적 계산치이지 실제 heap/VRAM peak 측정이 아니다. PDF board 전체를 벡터 텍스트/기하로 보존하지 않고 lossy JPEG raster로 평탄화하며, 지원하지 않는 drawing geometry는 거부한다. 상세는 [G3 이미지 편집 검수](../verification/G3-2-4-IMAGE-EDITING-2026-10-05.md)에 둔다. localStorage recovery는 source당 별도 key를 차지하며 브라우저 quota 영향을 받는다. WebGPU backend는 선택 불가이고 큰 문서 input-to-paint·GPU 자원·cache eviction은 측정하지 않았다. Production의 >500 kB chunk 경고와 WASM payload는 남아 있다.
