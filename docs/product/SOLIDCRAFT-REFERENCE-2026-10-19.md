# SolidCraft 참고 기록

검토일: 2026-10-19. 사용자 제안으로 지속 참고할 외부 사례에 등록했다. 우리 제품의 최종 목표는 자연어 2D·3D 생성·수정이며, 현재 작업을 2D에 한정해야 한다는 결정은 아니다. 이 문서는 자료 검토·설계 시사점이며 구현·실행 큐·도입 완료 기록이 아니다.

## 확인 범위

사용자가 제시한 [demo-0.8.gif](https://github.com/tangency-labs/solidcraft/blob/main/docs/screenshots/demo-0.8.gif), [저장소/README](https://github.com/tangency-labs/solidcraft), [MCP 문서](https://github.com/tangency-labs/solidcraft/blob/main/docs/mcp.md), [독립 기준 검증](https://github.com/tangency-labs/solidcraft/blob/main/docs/oracle.md), [데모 녹화 스크립트](https://github.com/tangency-labs/solidcraft/blob/main/examples/demo/record_ui.sh)를 참고했다. 첫 검토는 문서 중심이었고, 추가 검토에서 브라우저로 GIF의 돌출 준비, 바닥 스케치 편집, 재질이 적용된 케이스 장면을 직접 확인했다. 애니메이션 전체를 프레임별로 분석하거나 앱을 실행해 검증한 결과는 아니다. main 문서와 0.8 데모의 기능·시점이 같다고 가정하지 않는다.

추가 조사에서는 MCP의 `tools.rs`와 `backend.rs`에서 도구 검색·명령 실행·위상 조회가 공통 Backend를 통하는 부분도 읽었다. 확인한 소스 SHA와 다른 6개 프로젝트의 비교·적용 위치는 [외부 사례와 적용 기준](CAD-REFERENCE-ADOPTION-2026-10-19.md)에 기록했다.

## 참고할 구조와 우리 쪽 적용 판단

| 공식 문서에서 확인한 구조 | 우리 제품에 가져올 설계 관점 |
| --- | --- |
| MCP 도구가 UI·스크립트와 같은 엔진 명령을 사용 | 기존 Command/Query/Review/Apply 기반을 공통 실행면으로 유지. 모델이 직접 문서 원본을 수정하는 별도 경로를 만들지 않음 |
| 명령 검색, 설계 조회, 측정·위상 조회, 파라미터 변경, 스크린샷, Undo/Redo를 도구로 제공 | 판단 엔진이 기능을 발견하고 대상·결과를 수치와 화면으로 확인할 수 있게 설계. MCP라는 전송 방식의 도입 여부와 공통 도구 계약은 별도 판단 |
| 스케치·구속·피처 타임라인과 파라미터 변경 후 재생성 | 단발성 결과물보다 대화로 계속 수정 가능한 3D 원본·관계와 변경 영향이 중요. 기존 BRep·변수·재생성 기반과 연결할 수 있는 과제 검토 |
| batch 실패 시 checkpoint 기반 복구와 오류 반환 | 중간 성공이 남지 않는 transaction·취소·복구를 평가. 우리 기존 원자적 batch/계획 경계를 유지하며 정책 차이를 확인 |
| 생성 이후 inspect/measure/screenshot/export를 사용하는 세션 예시 | 자연어 생성 → 실행 → 수치/시각 피드백 → 재계획 → 저장/출력 흐름을 평가 |
| 해석식·독립 FreeCAD 결과 및 STEP 재열기로 참조 부품을 검증 | 같은 생성기로 만든 결과끼리만 비교하지 않고 치수·체적/면적·유효성·왕복을 독립 기준으로 확인 |

이 표는 도구/엔진 계약의 시사점이다. 기능을 우리 제품에 이미 연결했다고 보지 않는다. GIF에서는 좌측 모델/스케치 트리, 중앙 뷰, 스케치 상황별 우측 패널, 하단 피처 이력이 함께 보였다. 우리 UI에는 선택한 스케치/피처와 속성·영향 표시를 연결하는 관점을 적용할 수 있다. 각 조작의 사용성과 성능은 별도 실행 검토가 필요하다.

## 해석할 때 구분할 점

MCP는 판단 모델 자체가 아니라 모델/에이전트와 CAD 도구를 잇는 인터페이스다. 스크립트 데모가 성공했다는 사실만으로 임의 자연어 설계의 성공률을 보증하지 않는다. README는 데모의 녹화 스크립트와 가속 재생을 안내하고, MCP 문서에는 사전에 정의한 케이스 제작 절차도 있다. 우리는 미지의 자연어 요구, 후속 수정, 모호한 참조, 실패·복구와 저장/출력을 별도로 평가한다.

UI 외형·Rust/WASM·커널을 그대로 채택하는 결정을 하지 않는다. 기존 TypeScript/브라우저/커널 구조와 공통 실행·검증 계약의 적합성을 기준으로 참고한다. 저장소는 MIT/Apache-2.0 라이선스를 표기하지만, 이번에는 코드·미디어를 복사하거나 의존성을 도입하지 않았다. 실제 재사용 시 해당 파일과 의존성의 조건·표기를 확인한다.

## 제품 목적과 연결

[자연어 CAD 목적](NATURAL-LANGUAGE-CAD-PURPOSE-2026-10-19.md)에 따라 2D 또는 3D 중 자연어 생성·수정 능력을 가장 잘 검증하는 과제를 선택한다. “2D를 모두 끝낸 뒤 3D를 시작”이라는 고정 순서는 두지 않는다. 주거 도면은 학습·검증 자료 중 하나로 유지하고, 3D에서는 파라미터와 관계를 가진 단순 부품/케이스 같은 과제도 목적에 따라 선택할 수 있다. 구체적인 구현 착수는 별도 판단이다.
