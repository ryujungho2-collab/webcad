# 자연어 CAD·코파일럿 제품 목적과 판단 기준

결정일: 2026-10-19. 사용자 정정 반영: 최종 목적은 **자연어로 2D 도면과 3D 모델을 만들고 수정할 수 있는 CAD**이며, 외부 도면 이해·수정·복원은 이를 위한 학습·검증 단계다. 이 문서는 **제품 목적·개발 판단 기준**이다. 고정된 다음 작업, 새 실행 카드, 구현 완료 선언이 아니다. 이 문서가 최종 목적과 현재 개발 판단 기준을 소유하고, [NEXT-STEPS](../../NEXT-STEPS.md#현재-실행-큐)는 실제 실행 순서, [PROJECT-STATE](../../PROJECT-STATE.md)는 구현·검증 상태, [Copilot 가이드](../features/COPILOT.md)는 현재 지원 범위를 소유한다.

## 우리가 달성하려는 것

2026-10-25 편집 경험 기준: 모든 생성·편집은 **사람의 화면 조작 ↔ 코파일럿 자연어 ↔ MCP**로 이어져야 한다. PPT·포토샵·pen.dev처럼 대상을 선택하고, 눈앞의 핸들·속성·명확한 도구로 바꾸며, 필요하면 정확한 수치를 입력하는 경험을 목표로 한다. 이는 조작 경험의 비유이며 해당 제품의 기능을 그대로 복제한다는 뜻은 아니다.

직선/곡선과 평면/곡면 사이의 지원되는 변환도 한 번 생성하고 끝내지 않는다. 원본 윤곽·단면·파라미터·배치·관계를 유지해 다시 변환하고 다듬을 수 있어야 한다. 각 진입점은 같은 명령·대상 참조·검증·미리보기·Undo/Redo를 사용하고, 코파일럿이 만든 결과를 사람이 직접 수정한 뒤 코파일럿이 다시 이어받을 수 있어야 한다. 정보가 사라지는 변환은 손실과 복구 범위를 먼저 드러낸다.

완료 판정에는 **직접 편집 → 자연어 후속 수정 → MCP 수정 → 직접 재편집 → Undo/Redo → 저장·재열기**의 연속 과제를 포함한다. 수동 UI만 있거나 MCP 호출만 되는 기능을 이 기준에서 완성으로 보지 않는다. 모든 편집이 이미 연결됐다는 선언은 아니며, [로프트 연결 방식 왕복 편집](../implementation/LOFT-EDIT-HANDOFF-2026-10-25.md)이 이번에 검증한 범위다. 임의 자유곡면 제어점 편집·임의 솔리드의 곡면화·곡선 벽 변환은 별도 지원과 검증이 필요하다.

**사용자가 자연어로 의도·치수·배치·관계를 설명하면, 빈 캔버스에서도 원하는 2D 도면과 3D 모델을 생성하고 후속 대화로 수정할 수 있는 CAD를 만든다. 기존 코파일럿이 이 작업의 사용자 창구가 되며, CAD가 정확한 생성·편집·검증·저장·출력을 담당한다.**

예를 들어 “가로 6m, 세로 8m인 평면을 그리고 방 두 개와 복도를 배치해줘”, 이어서 “오른쪽 방을 300mm 넓히고 문 위치를 바꿔줘”라는 요청을 도면의 객체·치수·관계와 실행 계획으로 연결하는 것이 목표다. 3D에서는 “폭 80mm, 깊이 50mm, 높이 30mm인 케이스를 만들고 벽 두께 2mm와 나사 구멍 네 개를 넣어줘”, 이어서 “높이를 40mm로 바꾸되 구멍 배치는 유지해줘”처럼 생성·관계·재생성까지 연결하는 것이 목표다. 이 예시들은 제품 목표이며 현재 지원 완료를 뜻하지 않는다. 기존 도면의 수동 편집을 안내하는 보조 패널만으로 목적을 달성했다고 보지 않는다.

외부 도면은 도면 구성과 작성·수정 절차를 이해하고, 도구를 보완하고, 생성 결과를 평가하기 위한 학습·검증 자료다. 외부 도면을 가져와 복원하는 능력은 최종 제품 목적을 뒷받침하는 수단이다. 사용자가 먼저 외부 도면을 가져와야 자연어 작도를 시작할 수 있는 제품을 목표로 하지 않는다.

최종 범위는 2D와 3D를 포함한다. 2D는 현재 경험과 검증을 쌓는 중요한 축이며 제품의 영구적인 상한이나 모든 3D 작업의 필수 선행 단계가 아니다. 자연어 생성·수정의 완결성을 더 잘 입증하는 3D 과제라면 현재 구현 대상으로 선택할 수 있다. 기존 3D/BRep·스케치·파라미터 기반을 재사용하고, 2D/3D 각각의 기하·관계·출력 검증 기준을 명시한다. 이 결정이 모든 BIM·조립·제조 기능을 한 번에 구현한다는 뜻은 아니다. 과거 로드맵의 단계 번호를 현재 실행 순서로 해석하지 않는다.

코파일럿을 별도 CAD나 새 원본 저장소로 만들지 않는다. 기존 코파일럿에 자연어 의도 해석·도면 생성 계획과 도면 문맥 조회, 정확한 2D/3D 생성·편집, 결과 검증·복구를 연결한다. 판단 엔진은 규칙·템플릿, 외부 모델, 로컬 모델 중 이후 증거로 선택·교체할 수 있어야 한다. 판단 엔진의 구체적인 종류·구매·추가 학습 여부는 미정이다. 엔진 선택이 미정이라는 이유로 자연어 생성 능력을 제품 목표에서 빼거나 단순 수동 편집 편의 기능으로 대체하지 않는다.

## 우리가 소유할 기반과 판단 엔진의 역할

| 영역 | CAD 내부에서 보장할 책임 | 판단 엔진이 할 일 |
| --- | --- | --- |
| 문맥 조회 | 안정적인 객체/참조 ID, 단위·작업면·좌표계, 레이어·블록·문자·치수·관계, 잠금·숨김·편집 가능 여부와 지원 한계 제공 | 의도와 관련된 문맥을 조회하고 대상을 좁힘 |
| 정확한 생성·편집 | 2D 도형·문자·치수·블록과 3D 스케치·피처·파라미터·관계의 생성 및 편집 도구, 입력 계약·범위 검사·실제 기하 계산, 변경안과 영향, 원자적인 Apply와 한 작업의 Undo 경계 | 자연어 요구를 도면 구성·배치·치수·관계로 구체화하고 필요한 도구·인수·실행 순서를 계획 |
| 결과 검증 | 요청한 수치·위치·내용, 참조·주변 객체 보존, 단위·저장·출력과 손실 진단 | 검사 결과를 해석해 완료·재계획·추가 대상 확인을 선택 |
| 복구 | 게시 전 취소·오래된 계획 거절, 실패 원자성, 게시 후 Undo/Redo와 명시적인 원래 값 복원 | 유효한 복구 경로를 선택하고 사용자에게 결과 설명 |

판단 엔진이 문서 JSON·기하·잠금·이력을 직접 덮어쓰지 않게 한다. 조회된 대상이 곧 편집 권한이라는 뜻은 아니다. 후보가 모호하면 대상·범위를 사용자에게 확인하고, 미지원 연산은 가능한 도구와 제한을 설명한다. 기존 Review/Apply 경로를 재사용하며 자동 적용 범위를 넓힐 때에는 별도 정책과 평가 근거를 둔다.

도구 인터페이스를 정리할 때는 입력 대상 ID·문서 버전·좌표/단위·전제 조건, 지원 범위, 변경안/영향/진단, 취소·게시·복구 경계를 명시한다. 직접 UI와 코파일럿이 별도의 편집 계산을 갖지 않도록 한다. 이 항목은 목표 계약이며 모든 도구가 이미 연결됐다는 뜻이 아니다.

## 2D와 3D에서 갖춰야 할 작업 경험

- 빈 캔버스에서 자연어 요구를 받아 단위·치수·배치·관계를 가진 편집 가능한 2D 도면을 생성한다. 결과는 이미지나 설명문만이 아니라 CAD 객체여야 한다.
- 3D 과제에서는 스케치·구속·피처·파라미터와 원본 관계를 보존하는 편집 가능한 모델을 생성하고, 치수 변경·재생성·측정·출력을 연결한다. 화면 mesh가 그럴듯하다는 사실만으로 정확한 솔리드 생성 성공으로 판정하지 않는다.
- 후속 대화의 “오른쪽 방”, “방금 그린 문”, “이 선”, “이 면”, “방금 만든 구멍”을 현재 도면·작업 이력과 연결해 수정한다. 결정에 필요한 조건이 부족하면 핵심 조건을 확인하고, 채택한 가정은 드러낸다.
- 자연어 요구가 실행 가능한 지원 도구로 연결되고 요청 조건을 만족하는지 검사한다. 사용자가 모든 좌표와 명령 순서를 직접 작성해야만 작동하는 것을 목표 달성으로 보지 않는다.
- 외부 도면을 학습·검증하거나 기존 도면을 수정할 때는 단위·레이어·블록과 지원/제외/근사를 구분해 확인한다.
- 이름뿐 아니라 위치·주변 기하·레이어·블록과 선택 문맥으로 대상을 찾는다. 같은 이름의 Line/block이 많은 실제 도면에서도 수정 대상을 이해할 수 있어야 한다.
- 이동·복사·회전·크기·끝점·문자·스타일 등 지원하는 편집과 치수·스냅·출력을 연결한다. 작업면 밖 이동이나 공간 모델 수정으로 범위를 암묵적으로 넓히지 않는다.
- Preview에서 대상·수치·영향을 이해하고 Apply/취소를 선택한다. 오류와 진행 상태를 설명하고 실패 후 작업을 이어갈 수 있게 한다.
- 저장·재열기·DXF 및 종이 출력에서도 검증된 결과를 유지한다.

도면의 선·문 기호를 건축 벽·문 개구부로 자동 간주하지 않는다. 문 기호 축척 변경과 벽·개구부·치수의 연동 편집은 다른 능력이다. 사용자의 요청이 후자를 뜻하면 필요한 의미·관계가 실제로 존재하는지 확인하고, 없으면 도구 지원 범위를 설명한다.

## 검증과 작업 데이터의 목적

최종 평가는 **자연어 요구 → 의도·조건과 생성 계획 → 편집 가능한 2D 도면/3D 모델 생성 → 요구 조건 검사 → 후속 대화 수정 → 저장·재열기·출력**을 중심으로 한다. 처음 보는 요청·도면 유형에서도 치수·배치·관계와 사용자 의도를 만족하는지 평가한다. 배치가 여러 가지로 성립하는 과제는 원본 그림의 픽셀 일치만으로 정답을 판정하지 않는다. 3D는 유효성·치수·체적/면적·위상·관계·재생성과 형식별 왕복을 과제에 맞게 확인한다.

현재 학습·검증 단계에서는 외부 도면의 구성과 요구 조건, 작성·수정·복원 과정을 사례로 정리한다. 실제 외부 도면에서 **기준 가져오기 → 의도적인 수정 → 검토·적용 → 결과 검사 → Undo/Redo 및 직접 편집 복원 → 저장·재열기·출력**을 평가한다. 복원 성공만으로 수정의 건축적 타당성을 판정하지 않는다. 가져오기 때의 손실과 편집/복원 과정에서 새로 생긴 차이를 분리한다.

주거 도면은 첫 기준 사례다. 이후 단위·레이어 관행·블록/참조·곡선/해치·규모가 다른 도면으로 넓혀 일반성을 확인한다. 평가용 도면·자연어 과제는 사례 작성/튜닝에 쓰는 자료와 분리한다. 파일 개수나 테스트 통과 개수만으로 제품 완성을 선언하지 않는다.

수집할 작업 기록의 목표는 자연어 요청·명시 조건·가정, 생성 전/후 또는 수정 전/후 상태와 문맥, 도면 구성·배치·관계의 판단 근거, 실행 도구·인수, 변경/영향, 기대 결과와 검사 결과, 실패·취소·복구, 저장/출력 결과다. 검증·재현·참고 사례가 첫 용도이며, 기록 기능과 데이터가 이미 구축됐다는 뜻은 아니다. 추가 학습은 충분한 검수 사례와 필요성이 확인된 뒤 결정한다. 외부 도면의 사용 권한과 데이터 처리 범위도 별도로 확인한다.

성공률, 오선택·의도 밖 변경, 요청 수치/참조/주변 형상 보존, 실패 원자성·복원 정확성, 사용자의 재입력·도구 전환·복구 부담, 처리 시간을 함께 본다. UI는 기능을 드러내는 데서 그치지 않고 사용자가 대상을 확인하고 작업을 끝낼 수 있는지 평가한다.

## 현재 근거와 미완료 범위

[주거 수정·복원 검증](../implementation/EXT-CIVIL-RESTORE-01-2026-10-19.md)은 명령 경로와 직접 UI에서 성공한 첫 사례다. 코파일럿이 이 작업을 자율 수행했거나 자연어로 새 도면/모델을 생성했다는 결과는 아니다. [외부 도면 2차](../implementation/EXT-CIVIL-02-2026-10-19.md)·[3차](../implementation/EXT-CIVIL-03-2026-10-19.md)의 지원 한계도 유지된다.

현재 코파일럿은 로컬 조회·guided 작업·제한된 gateway 계획의 검토/적용 범위이며, 실제 모델 제공자 연결이나 모든 2D 편집 도구 노출이 완료된 상태가 아니다. 세부 범위는 기능 가이드에서 관리한다. 단일 도면 검증으로 다양한 실무 도면 지원, 의미 기반 건축 편집, 임의 자연어 자동화를 완료했다고 보지 않는다.

## 다음 작업을 고르는 기준

자연어로 정확한 2D 도면과 3D 모델을 생성하고 대화로 수정하는 목적을 가장 크게 막는 문제를 선택한다. 의도 해석·생성 계획, 도면 구성·관계 표현, 생성/편집 도구, 문맥 조회, 검증·복구, 판단 엔진 연결, 학습·평가 사례, UI·성능 중 어느 것이든 근거에 따라 실행 작업이 될 수 있다. 외부 가져오기 개선도 이 목적에 기여하는 학습·검증 필요성으로 판단한다. 위 목록은 강제된 구현 순서가 아니다.

작업을 선택할 때는 해결할 사용자 과제, 현재 실패 근거, 지원/비지원 범위, 실제 도면과 독립적인 완료 판정을 정한다. 선택된 작업만 NEXT-STEPS의 실행 큐에 반영한다. 이번 결정은 목적 정리이며 새 기능 구현이나 특정 작업 착수를 뜻하지 않는다.

## 지속적으로 참고할 외부 사례

[외부 사례와 적용 기준](CAD-REFERENCE-ADOPTION-2026-10-19.md)에서 SolidCraft 외에 Zoo Design Studio, CadQuery, replicad, FreeCAD, SolveSpace, Online 3D Viewer를 역할별로 비교한다. 공통 명령·수정 가능한 원본·면/모서리 조회·구속 피드백·3D에서 도면까지의 흐름을 기존 코드에 연결하고, 구멍 있는 판과 케이스의 생성·후속 수정 과제를 평가 후보로 둔다. 2D 전체 완료를 이 과제들의 선행 조건으로 두지 않는다.

[SolidCraft 검토 기록](SOLIDCRAFT-REFERENCE-2026-10-19.md)을 자연어 CAD의 명령 인터페이스·파라메트릭 모델링·피드백·독립 검증 참고 자료로 유지한다. 외형 모방이나 커널 교체를 결정한 것이 아니다. 외부 데모의 재생·스크립트 실행과 미지의 자연어 요청 처리 능력은 구분한다. 참고 자료가 자동으로 다음 구현 카드가 되지는 않는다.
