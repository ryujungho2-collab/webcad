# Courtyard Commons — 졸업설계 규모 CAD 검증

2026-10-13 후속: 최초 감사의 공백을 B2/W1에서 보충하고 R5 56부품·14도면·10페이지를 발행했다. [최신 구현·한계](../implementation/G6-D6-W1-ARCHITECTURAL-ISSUE-2026-10-13.md). 아래 내용은 최초 감사 시점의 기록이다.

후속 P0/P1 수정(2026-10-12): 성능·저장 단면 레이어·증명 가능한 선 그래프 참조 보충 및 첫 analytic HLR 입면/숨은선을 구현했다. [수정 검수](../implementation/COURTYARD-P0-P1-FIXES-2026-10-12.md), [수정 프로젝트](../../output/projects/courtyard-commons/p01-fixed/README.md). 아래 표와 최초 판정은 수정 전 발견 기록이다. 현재 남은 다음 우선순위는 G6-D4-H1 건축 도면 표현이다.

사용자가 선택한 **3층 중정형 도서관·메이커센터**를 공개 CAD 명령으로 작성하고 실제 브라우저의 편집·저장·출력 경로를 검사한다. 단일 방의 소형 예제에서 벗어나 복수 층·계단·반복 외피·모델 연관 도면·시트 세트를 함께 다루는 검증이다. 고려대학교의 공식 심사 기준이나 졸업설계 제출 완료를 주장하지 않는다.

## 프로젝트와 판정 기준

가상 54×44m 대지, 36×28m 외곽, 12×14m 중정, 층고 4,200mm. 실제 슬래브 체적에서 계산한 바닥 면적은 **840 + 792.88 + 792.88 = 2,425.76㎡**다. 56개 등록 부품에 외벽/창 띠/출입구, 3개 층의 바닥·구획벽·기둥·중정 가장자리, 두 U자 계단, 지붕과 경사 원통 채광부 연구안을 포함한다.

설계 의도·프로그램 배분·건축 설계 자체의 미완료 사항은 [설계 브리프](../../output/projects/courtyard-commons/DESIGN-BRIEF.md)를 따른다. 이 보고서는 **CAD 제품 공백**, **선택한 설계의 미완료**, **단순 fixture 오류**를 구분한다. 엘리베이터·설비·피난·구조·외피 상세를 아직 설계하지 않은 것을 곧바로 CAD 결함으로 세지 않는다.

## 확인된 기반

- 동일 문서의 명령 검증 → 분리된 proposal → 원자적 publish/History → revision/generation 알림을 캔버스와 Review가 공유한다. 모델·치수·도면을 독립적인 임시 상태로 각각 편집하는 구조는 아니다.
- 실제 BRep Boolean 외벽/개구부, 돌출 계단, 정확 체적, 기본 평면의 단면, 저장·Undo/Redo와 도면 시트 출력 경로가 있다.
- 미지원 기하와 참조 소멸은 명시적으로 실패한다. 잘못된 입면도를 성공처럼 출력하거나 잃은 참조를 가까운 선으로 조용히 갈아 끼우지 않는 것은 유지해야 할 계약이다.

## 다음 구현 순서

**보충을 먼저, 전체 건축 도면에 필요한 기하 추가를 그다음**으로 진행한다.

1. **G6-D6-P1을 앞당긴다.** 주석/이름/표시/시트 배치가 원본 BRep를 반복 계산하지 않도록 한다. source revision 기반 section cache, 영향을 받은 view만 갱신, 같은 source를 쓰는 scale/placement 후보 공유. 정확도·stale·잠금·Undo 계약을 유지하고 이 56부품/5도면을 회귀 fixture로 사용한다. 첫 실행과 warmed 실행을 구분하며 평균 하나로 대규모 성능을 주장하지 않는다.
2. **G6-D4-R1 단면 편집·참조 안정화 보충**을 새 카드로 둔다. 저장 뷰의 레이어·종이 소유권을 유지하는 Review, 영향/미영향 뷰 진단, 보존 가능한 원본 대응과 복구 안내를 구현한다. 명확히 대응되지 않는 edge를 추측 연결하지 않는다. 복구 후 연관 주석/치수와 시트까지 확인한다.
3. **G6-D3-B1 → B2.** 이 프로젝트의 Boolean 창/문·슬래브·돌출 계단을 첫 일반 BRep 가시 윤곽/입면 fixture로 삼고, 가려진 선과 여러 부품의 가림을 확장한다. 평면 선을 수작업 복사해 입면 완료로 세지 않는다.
4. **G6-D4-H1을 건축 마감 전에 진행한다.** 아래 PDF 검수에서 확인한 cut-only 평면의 공백을 해결한다. 절단선과 절단면 아래/뒤 투영을 합성하고 crop/depth/가림·선 굵기·닫힌 loop 해치·뷰 이름/번호를 검수한다. 일반 BRep 투영에 의존하며, 모델 참조와 출력 축척을 유지한다.
5. **X6-D2-E1.** 실제 경사 채광부의 타원 단면, 유한 crop, 치수/시트 참조까지 연결한다.
6. **G6-D6-W1의 건축 마감.** 같은 프로젝트에서 층고·외피 개구부·계단·중정 변경 → 평면 3장·입면 4면·단면 2개·상세 → 축척 도면 세트 → 저장/재열기를 끝낸다. 이후 spline/임의 단면과 제작 기능의 순서를 재평가한다.

전체 session owner 통합은 G1 후속으로 유지한다. 이번에 재현된 UI 충돌은 이미 직접 수정했으며, 재현 근거 없이 모든 캔버스 기능을 재작성하는 작업으로 확대하지 않는다.

## 실제 출력·UI 검수 결과

2026-10-12: **56부품 / 602 문서 객체 / 평면 3개·단면 2개 / A2 1:100 4페이지**를 저장했다. SVG/DXF와 앱에서 다운로드한 PDF를 남겼다. PDF 4페이지를 Poppler로 독립 렌더링하고 전부 시각 검수했다. 파일 생성·재열기 성공과 건축 도면 완성도를 구분한다.

- 실제 Three.js 장면에 56부품이 도달했고 창 폭 28,000→30,000mm 입력이 한 History로 적용됐다. 1층 평면은 unresolved, 변경되지 않은 3층 평면은 resolved였다. 실제 Ctrl+Z/Y 및 cache 재열기에서 기하/도면/시트 참조가 보존됐다.
- 이 브라우저 시나리오의 **14개 감사 assertion 통과**에는 저장 단면 Review의 명시적 실패를 관측하는 검사가 포함된다. 저장 단면 편집 기능이 통과했다는 뜻이 아니다. 관련 별도 회귀 8 workflows/226 checks를 더해 이번 작업에서 9 workflows/240 checks를 실행했다. 전체 Node suite 재실행은 아니며 이전 1,151개 결과와 구분한다.
- 첫 장면 준비 약 8초, 실제 개구부 입력→적용 약 12~13초(Vite/자동화 환경, native-report의 해당 실행 값). 주석 약 3초·시트 Apply 약 118초(스크립트)는 다른 경로의 측정이다.
- **건축 표현 공백:** 평면은 수평 절단 교선만 표시한다. 1,500mm 아래에 있는 900mm 중정 난간, 바닥 경계, 계단의 전체 진행이 보이지 않는다. 창 개구부로 긴 벽 선이 끊긴 상태도 배경 투영/창 기호 없이 전달된다. 단면도 역시 뒤쪽 형상·해치·절단선과 배경선의 위계가 없다. 절단 연산의 성공을 건축 평면도 완료로 볼 수 없다. G6-D4-H1을 일반 BRep 투영 다음으로 앞당긴다.
- **프로젝트 작성 부족:** 프로그램 주석 3개가 같은 첫 교선에 연결되어 긴 리더가 한 점으로 모인다. 이는 스크립트가 첫 edge를 재사용한 결과이며 엔진 결함으로 분류하지 않는다. 공간별 앵커 선정, 단면 이름/번호, 충분한 치수·문창·가구·해치·계단 기호를 보완해야 한다. 현재 출력은 검증 증거이며 제출용 정리 도면이 아니다.
- **설계 부족:** 떠 있는 경사 채광부는 unsupported ellipse 검사용 연구안이다. 지붕 접합·채광 계획이 해결된 요소로 취급하지 않는다. 설계 프로그램/동선/구조/접근성을 발전시킨 뒤 졸업설계 수준을 논해야 한다.

판정: **CAD 문서·기하·캔버스·History·출력 연결은 작동하지만, 현재 상태로 졸업설계 도면 생산을 맡기기에는 성능·참조 편집·건축 표현이 부족하다.** 다음 구현은 G6-D6-P1이다. 이 프로젝트를 반복 검증 fixture로 유지한다.
