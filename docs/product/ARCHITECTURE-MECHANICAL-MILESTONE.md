# 1차 건축·기계 CAD / 2차 통합 제작 목표

갱신일: 2026-10-09. 사용자 목표를 반영한 **계획**이다. 이 문서를 추가한 것으로 기능 구현·브라우저 검수를 완료했다고 표시하지 않는다. 현재 구현은 [PROJECT-STATE](../../PROJECT-STATE.md), 실행 순서는 [NEXT-STEPS](../../NEXT-STEPS.md)가 소유한다.

## 목표와 우선순위

**1차: 하나의 정밀 모델을 숫자로 수정하고, 같은 모델에서 건축·기계 도면과 분해도를 만든다.** 정면·평면·측면·사시도를 바꿔 보며, 지름·길이와 명시적으로 연결된 관계를 수정하고, 연관 도면을 갱신해 출력하는 작업을 끝낸다.

**2차: 아트보드·벡터/이미지 편집·프로토타입·슬라이드·LLM을 통합한다.** 1차의 공통 문서·선택·명령·Preview/Apply·History를 재사용한다. 사용자가 직접 수정하든 LLM으로 수정하든 같은 검증과 결과를 얻도록 한다. 기존 구현은 유지하며 1차에 필요한 아트보드/출력 기반은 재사용한다. 1차 완료 전에 2차 기능을 모두 확장할 필요는 없다.

건축·기계는 별도 엔진으로 나누지 않는다. Geometry/Constraint/Dependency가 원본이고, 분야별 도구·속성·도면 표현을 그 위에 둔다. 완전한 BIM, 제조용 모든 공차/기호, 조립 운동 해석까지 첫 묶음에 포함하지 않는다. 이후 확장을 막지 않는 참조·단위·부품 경계를 먼저 마련한다.

## 현재 기반과 남은 연결

2026-10-09 코드 조사 결과다. 아래 기반은 해당 사용자 workflow 전체가 검수됐다는 뜻이 아니다.

| 영역 | 확인한 기반 | 1차 목표에서 필요한 연결 |
| --- | --- | --- |
| 뷰 | `CadViewport.setStandardView`, Ribbon/검색의 Top·Front·Right·Isometric, 투영 전환 | 명명된 모델 뷰 저장·재열기, 정투영/원근 구분, 도면 뷰의 원본 연결 |
| 수치 수정 | `PropertiesPanel`의 primitive 치수와 `update-primitive`, 스케치 구동 치수·변수/수식 | 지름/반지름 전환과 길이 입력의 일관된 검토, 영향 관계·재생성·실패 복구 |
| 치수 | 일반 지름·각도 연관 주석과 스케치 구동 치수 | 표시 치수와 모델을 바꾸는 구동 값을 명확히 구분하고 가능한 편집 경로로 인계 |
| 모델·출력 | 스케치/돌출 등 솔리드 작업, 기존 2D 출력·아트보드 기반 | 동일 모델에서 파생되는 정투영 도면, 단면·숨은선·축척·연관 치수 |
| 분해 표현 | 객체 transform, 별도 Scene 표현 기반 | 부품 identity·조립 위치와 분리된 3D 분해 방향/거리·저장 뷰. 기존 곡선 Explode와 구분 |

`CadScene.tracks`의 현재 pose는 2D 위치·opacity 계약이다. 이를 3D 조립체 위치로 재해석하지 않는다. 기존 벡터 Component 역시 3D assembly 지원으로 간주하지 않는다. 공유할 수 있는 ID·참조·transaction 경계만 재사용한다.

## 반드시 지킬 모델 계약

- **보기 방향:** 모델을 돌려 보는 조작은 카메라/뷰 변경이다. 실제 부품 Rotate는 형상 배치 편집으로 명시한다. 정면도·평면도는 정투영으로, 설명용 사시도는 정투영/원근을 선택하게 한다.
- **분해도:** 원래 조립 위치와 부품 ID를 보존한다. 표시 위치는 조립 위치에 부품별 분해 방향·거리와 전체 분해량을 적용해 계산한다. 분해량 0에서 정확히 조립 상태로 돌아온다. 표시 간격이 길이 측정·질량·실제 조립 관계를 바꾸지 않는다.
- **숫자 수정:** 지름 Ø20→Ø25, 길이 80→100은 모델의 구동 parameter를 수정한다. 주석 text 변경으로 형상 변경을 흉내 내지 않는다. 지름은 반지름의 표시/입력 변환으로 같은 원본 값을 사용한다. 다른 부품은 저장된 구속/변수 관계가 있을 때만 따라간다.
- **건축 뷰:** 평면도는 단순 Top 화면과 구분한다. 절단 높이·보이는 범위·개구부와 단면선을 정의한다. 입면·단면·사시도도 같은 모델을 참조한다. section/crop은 원본 솔리드를 잘라 버리지 않는다.
- **도면:** 모델은 실제 단위를 유지하고 종이 축척만 별도로 적용한다. 파생 선과 치수는 원본/뷰 참조를 보존한다. 참조 소멸·모호함은 표시하고 재지정을 요구하며, 임의의 가까운 edge에 연결하지 않는다.
- **편집 경험:** 대상 선택 → 구동 값/참조 확인 → 숫자/드래그 입력 → 영향 preview → Apply → 연관 뷰/치수 확인을 공유한다. 기존 commandInteraction과 atomic transaction을 재사용하고 AI 전용 문서 수정 경로를 만들지 않는다.

## 작은 구현 묶음

아래는 미구현 계획이다. 한 요청에서 한 하위 묶음을 구현·검수·기록한 뒤 멈춘다. 기존 CAD B/X와 G6-A를 대체하거나 완료로 올리지 않는다.

| 순서 | 묶음 | 결과·검수 경계 |
| --- | --- | --- |
| 1 | G6-A1 모델 뷰 저장 계약 | 현재 카메라 경로 조사, 이름/정투영·원근/방향/target/프레이밍을 저장·복원. 문서·명령·migration·Undo/재열기 검수. 외부 adapter 불필요 |
| 2 | G6-A2 뷰 UI | 현재 Ribbon/검색/뷰 선택에 저장·호출·이름 수정 연결. 같은 모델의 표준 뷰 전환과 Fit. 카메라 상태만 바뀌고 모델 측정/배치는 불변인지 실제 browser 확인 |
| 3 | CAD 수치 편집 pilot | cylinder 지름·길이와 기존 스케치/돌출 구동 경로를 각각 조사. 먼저 한 경로의 단위·영향 preview·Apply/Undo·오류 복구를 검수한 뒤 다른 경로 확장. 임의 BRep 치수 편집을 약속하지 않음 |
| 4a | 부품/조립 위치 계약 | 소규모 독립 솔리드 부품 집합·안정 ID·조립 위치와 참조/삭제 정책. 전체 mate solver는 별도 후속 |
| 4b | 비파괴 분해도 | 4a에 부품별 방향/거리·전체 분해량·원상 복귀·저장 뷰를 연결. 선택/picking과 측정이 표시 위치·실제 위치를 혼동하지 않는지 확인 |
| 5a | 모델 연관 정투영 | 저장 뷰에서 파생된 선의 source 참조·갱신·실패 정책. 윤곽선에서 시작해 숨은선 처리의 정확성과 지원 형상을 검수 |
| 5b | 건축 절단 평면/단면 | 절단 높이·범위·개구부·단면선, 원본 불변. 기존 B5 면/절삭 등 필요한 선행 카드는 별도 요청으로 먼저 완료 |
| 6 | 도면 시트/치수·출력 | 5a/5b의 뷰를 기존 보드/출력에 연결. 축척·정렬·연관 치수·PDF/SVG/DXF 지원을 포맷별 검수. 화면 screenshot을 정확한 도면 출력으로 취급하지 않음 |
| 7 | 두 분야 전체 workflow | 아래 건축·기계 예제의 변경/재생성/출력·저장/이력·성능 검수. 통과 후 2차 확장 순서를 다시 결정 |

G6-A1/A2는 [Axo 설계](../architecture/RVT-IFC-AXONOMETRIC-INTEGRATION.md)의 첫 범위를 더 작게 나눈 것이다. section/crop/출력까지 A1 하나에 넣지 않는다. CAD 면 작업·Hole 등은 [CAD 구현 카드](CAD-BASICS-IMPLEMENTATION-PLAN.md)의 기존 ID를 유지한다. 사용자가 별도로 요청한 [G5-B2 단일 2D Move](../implementation/G5-B2-COPILOT-MOVE-2026-10-09.md)는 먼저 구현했다. 추가 편집 command와 실제 LLM 확장은 2차 후속이다.

## 1차 완료를 판정할 사용자 작업

**기계:** 3–5개 부품의 축·부시·판 예제에서 지름과 길이 수정 → 명시적 관계를 가진 부품만 재생성 → 정면/평면/측면/사시도 확인 → 분해량 조절·복귀 → 치수 포함 도면 출력. 조립/분해 상태를 왕복해도 실제 부품 배치와 형상은 변하지 않아야 한다.

**건축:** 작은 단층 예제의 벽·바닥·개구부를 작성 → 두께/높이/개구부 폭 수정 → 지정 절단 높이의 평면·입면·단면·사시도 갱신 → 치수와 축척(예: 1:50)을 가진 도면 출력. 첫 예제에서 형상/parameter로 구현한 관계와 실제 BIM semantic object를 구분해 보고한다.

두 예제 모두 Apply 실패/Cancel의 원본 불변, 잠금·소멸/모호한 참조, Undo/Redo, save/reload 후 identity/뷰/치수 관계 보존을 검증한다. 실제 browser에서 발견→선택→정밀 입력→영향→오류 수정→적용→출력까지 실행한다. 뷰 전환·수치 반복 편집·재생성·출력 지연을 같은 fixture/환경으로 측정하며 근거 없는 성능 목표 달성을 보고하지 않는다.

완료는 카메라 버튼이나 숫자 필드의 존재가 아니라 두 작업의 끝까지 이어지는 경험으로 판단한다. 최신 전체 검수 기준선은 PROJECT-STATE의 G5 기록을 따르며, 이 목표의 새 건축·기계 workflow 검증은 아직 수행하지 않았다.
