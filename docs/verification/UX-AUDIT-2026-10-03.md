# 기계 설계·건축 도면 작업 흐름 점검

> 단계 기록: 아래 구현·검수 수치는 해당 시점의 근거다. 최신 지원 범위는 [CAD-BASICS](../product/CAD-BASICS.md), 최근 전체 검수는 [PROJECT-STATE](../../PROJECT-STATE.md), 다음 실행 순서는 [NEXT-STEPS](../../NEXT-STEPS.md)를 따른다.

점검일: 2026-10-03. 로컬 코드와 별도 미리보기(127.0.0.1:5185)를
검사했다. 스케치 사각형 작성, 치수·직접 편집, 내부 원을 포함한 단면
선택, 6,000×4,000 독립 도형의 2D 회전을 화면에서 재현했다.
실무 사용자 인터뷰나 작업 시간 벤치마크는 수행하지 않았다.
아래 재현 결과는 최초 점검 당시 상태다. 후속 구현 결과는 다음과 같다.

## 후속 구현·검증 (2026-10-03)

- 2D 회전의 법선 축과 평면 내 이동, Inspector/기즈모의 축 제한 수정.
  Fit과 2D 전환 애니메이션이 충돌해 시선이 기울어지는 오류도 수정.
- 사각형 모서리·변 편집 구현. 반대편을 고정하며 회전·치수 참조 유지.
- 스케치 이동·회전·균일 배율·복사·Offset·Trim/Extend 활성화.
  복사는 선택 내부 구속과 치수를 새 참조로 유지한다.
- 구속 충돌 시 요청이 솔버에 의해 조용히 취소되는 문제 수정.
  충돌 구속 종류/ID를 표시하고 문서·History를 보존한다.
- 연속 작성, 단위가 포함된 첫 점 좌표 입력, 단계별 Esc 구현.
  화면 검사에서 드러난 Esc 중복 처리와 선택 해제도 수정했다.
- Width/Height 구분, 단위 입력, 삭제 시 소유 구속·치수 정리 구현.
  후속 솔리드가 참조하는 프로파일 삭제는 여전히 원자적으로 거절한다.
- 288개 테스트 통과. 실제 React UI·Worker 검사 13개 통과.
  포인터 모서리/변 드래그, 이동 기즈모, Trim/Extend와 Undo/Redo도
  별도 브라우저 화면에서 확인했다.

점검 당시 후속 항목은 캔버스 구동 치수·구속 기호, 자동 제약, 구멍 포함 영역 선택,
면 위 스케치, 보조선과 기계/건축별 납품 흐름이었다.
이 중 완료된 흐름은 [순차 구현 검수](WORKFLOW-VERIFICATION-2026-10-03.md),
현재 지원 범위는 [CAD-BASICS](../product/CAD-BASICS.md)를 따른다.

## 다음 작업 결정 (2026-10-03)

당시에는 캔버스 구동 치수·구속 표시, 기준점 기반 조작, 자동 구속·보조선,
구멍 포함 영역·돌출, 건축 표현·납품 순서를 결정했다. 현재의 다음 작업은
[NEXT-STEPS](../../NEXT-STEPS.md)에 있다. 아래 문제와 코드 위치는 최초
점검 당시의 근거이며, 현재 미구현 과제나 현재 코드 줄 번호를 뜻하지 않는다.

## 판단

최초 점검에서 가장 큰 마찰은 만들 수 있는 형상의 수보다, 만들고 수정하는
동작의 일관성과 설계 의도를 확인하는 피드백에 있다. 사용자가 작업
대상과 치수를 다루는 동안 도구 종료, 선택 상태, Sketch 소유 여부,
Object/Direct 모드, Inspector 위치를 계속 의식해야 한다.

기계 설계와 건축 도면은 각각 완성된 작업 흐름을 제공해야 한다.
공통으로 그리기·선택·정밀 입력·Undo 규칙을 갖추고, 작업별로 필요한
편집 도구와 납품 결과를 설계하는 것이 적절하다.

## 실제 화면에서 확인한 문제

| 우선순위 | 재현한 동작 | 점검 당시 결과 | 당시 필요한 개선 |
|---|---|---|---|
| P0 | 2D XY에서 6,000×4,000 사각형을 만든 뒤 `R → 90 → Enter` | Rotation X=90. 사각형이 화면에서 선처럼 보이며 투영 면적은 0으로 표시되고 프로파일이 무효가 됨 | 2D 기본 회전은 활성 작업 평면의 법선 축을 사용. 기준점과 각도를 분명하게 표시 |
| P0 | 스케치 사각형의 Direct 모서리 핸들을 드래그 | 핸들과 드래그 동작은 제공되지만 원래 형상으로 돌아가며 `No change or invalid sketch edit.` 표시 | 반대쪽 모서리를 기준으로 폭·높이를 바꾸는 편집 정책과 구속을 존중하는 드래그 구현. 지원하지 않는 핸들은 실행 전 안내 |
| P0 | 스케치 형상을 선택하고 Modify 확인 | Move/Rotate/Scale/Duplicate/Trim/Extend가 비활성화. Offset도 Sketch 소유 형상에서는 제한 | 스케치 전용 이동·회전·복사·트림·오프셋을 구속/참조 유지 규칙과 함께 제공 |

| P1 | 스케치 사각형에 Width/Height 치수 추가 | 오른쪽에 두 값이 모두 `Distance`로 표시됨. 도형 위에는 해당 구동 치수와 구속 기호가 표시되지 않음 | 캔버스 치수 편집, 대상 강조, 폭/높이 의미 보존, 구속별 표시와 문제 위치 안내 |
| P1 | 폭·높이 구속이 있는 스케치 사각형 삭제 | 삭제가 거절되며 일반적인 오류 메시지 표시 | 삭제를 막는 제약·후속 피처를 설명. 소유 제약 정리와 외부 참조 처리 정책을 한 Undo 단위로 제공 |
| P1 | 사각형 내부에 원을 그린 뒤 둘을 선택해 구멍 포함 단면 돌출 | Extrude 비활성화. 경계/내부 구멍을 하나의 선택 영역으로 다룰 수 없음 | 닫힌 영역 선택, 외곽/내곽 루프 분류, 복수 영역 선택과 돌출 결과 미리보기 |

첫 점 지정 후 사각형의 `폭,높이` 수치 입력은 작동했다. OSNAP, Ortho,
윈도우/교차 선택, 일부 직접 편집과 원본 종속 재생성도 이미 있다.
이 기능들을 일관된 작업 세션으로 연결하는 것이 필요하다.

## 코드에서 확인한 추가 마찰

- `App.tsx:204`의 정밀 변환 기본 축은 작업 평면과 관계없이 X다.
  2D 회전 문제는 화면 결과와 일치한다. 이동도 작업 평면 좌표와
  월드 좌표의 의미를 명확하게 나눠야 한다.
- `App.tsx:819`의 그리기 완료 경로는 항상 도구를 종료한다.
  `shortcutRouter.ts:49`는 선택 여부로 R의 의미를 바꾼다.
- `registerSketchCommandHandlers.ts:24`는 사각형 모서리 편집을 거절한다.
  선/폴리라인 세그먼트 이동은 있으나 사각형 세그먼트 이동은 없다.
- `registerSketchCommandHandlers.ts:101`은 참조 제약이 하나라도 있으면
  형상 삭제를 거절한다. 사용자에게 어떤 제약인지 알려주지 않는다.
- `SketchInspector.tsx:81`은 전체 스케치의 제약 목록을 표시한다.
  선택 형상과 제약의 시각적 연결, 문제 위치 강조가 필요하다.
  현재 숫자 입력은 `type="number"`라 식·단위가 포함된 입력과 맞지 않는다.
- `CadViewport.tsx:2712`는 아직 첫 점을 지정하지 않은 수치 입력을
  처리하지 않는다. 첫 점의 절대 좌표, 이어지는 점의 상대 좌표,
  길이/각도, Tab 잠금을 하나의 커서 입력 체계로 연결해야 한다.
- 그리기 스냅은 좌표를 맞추지만 `handleDrawingCommit`은 형상만 추가한다.
  Coincident/Horizontal/Vertical 관계를 지속 제약으로 자동 생성하는
  경로가 없다. 눈으로 붙어 보인 선이 이후 편집에서 함께 움직일
  것이라는 기대를 충족하지 못한다. 자동 제약은 미리 표시하고
  일시적으로 억제할 수 있어야 한다.
- `Sketch.ts`에는 평행·수직·접선·동심·동일·대칭 제약과 보조선 상태가
  없다. `workPlane.ts`의 선택은 XY/XZ/YZ뿐이며 면 위 스케치와
  연관 투영/외부 참조 작업 흐름도 없다.
- 리본 Extrude는 즉시 기본 10 mm를 생성하고 Revolve는 기본 360°를
  생성한다. Inspector에서 생성 전 값을 입력하는 경로는 있으나,
  매개변수 입력과 미리보기가 통합된 피처 편집 세션은 필요하다.
- `dxfParser.ts`의 가져오기는 LINE/LWPOLYLINE/POLYLINE/CIRCLE/ARC 부분집합이다.
  블록·문자·치수·해치 등은 가져오기 경고 대상이며, 벌지 폴리라인도
  건너뛴다. `Layer.ts`는 선종·선굵기·색상 속성을 갖지 않는다.
  기본 DXF/PDF 출력이 있다고 완성된 건축 도면 교환을 보장할 수 없다.

## 권장 구현 순서와 완료 기준

### 1. 기본 조작과 명령 세션

2D 회전 축, 사각형 직접 편집, 연속 그리기, 재실행, 단계별 취소를
먼저 개선한다. 커서 근처에서 길이/각도/좌표를 수정하고 잠그며
미리보기 후 확정하는 흐름을 만든다. 이동·복사에는 기준점→대상점
입력을 제공한다. 선택이 남아도 새 도형 생성 명령의 의미가 안정적이어야 한다.

완료 기준:

- XY/XZ/YZ에서 평면 내 90° 회전 후 해당 평면과 면적 유지.
- 같은 도구로 도형 5개를 연속 작성하고 부분 입력 취소 후 계속 작성.
- 첫 점 `(0,0)`과 두 번째 점의 상대 좌표를 키보드로 지정.
- 사각형 모서리/변 편집에서 앵커와 구속 처리 결과가 미리보기와 일치.
- 각 확정은 한 Undo 단위, 취소와 실패는 문서 변경 없음.

### 2. 스케치 편집과 설계 의도 표시

스케치 내 이동·복사·Trim·Offset, 보조선, 기본 자동 제약을 제공한다.
치수와 구속 기호를 캔버스에 표시하고, 클릭하면 대상 형상을 강조하고
편집할 수 있어야 한다. 선택 객체에 해당하는 제약을 찾기 쉽게 하고
충돌 시 관련 제약·형상 및 해결 선택지를 보여준다.

완료 기준:

- 스냅으로 연결한 선은 지속 Coincident 관계를 가지며 이후 편집에도 연결 유지.
- 치수를 도형 위에서 선택해 `100→120`으로 수정하고 연결 솔리드까지 갱신.
- 구속된 형상이 움직이지 않을 때 문제 제약을 캔버스에서 식별.
- 복사한 스케치 형상의 내부 구속과 외부 참조 처리 결과가 명확함.

### 3. 기계 설계의 대표 흐름 완성

닫힌 영역과 구멍, 면 위 스케치, 연관 투영, 보조 축, 평행/수직/접선/
동심/동일/대칭 제약을 우선한다. 이어서 Mirror/Pattern, 피처 매개변수
미리보기, 실패한 엣지 참조 복구 작업을 연결한다.

검수 과제: 100×60×8 판에 위치 치수로 배치된 구멍 4개를 만들고,
폭과 구멍 간격을 바꾼 뒤 관계·구멍·후속 모따기와 Undo를 확인한다.

### 4. 건축 도면의 대표 흐름 완성

일반 2D 도면에서는 불필요한 구속을 강제하지 않으면서 정확한
기준점/상대 좌표 입력, 반복 Offset/Trim/Extend, Join/Break, 블록/
인스턴스, 해치·문자·연속 치수, 선종·선굵기와 레이아웃을 연결한다.
Sketch의 설계 의도를 사용해야 하는 상황과 일반 도면 편집의 관계를
명확히 해야 한다.

검수 과제: 6,000×4,000 평면에 150 mm 벽체와 문·창을 만들고,
벽 한쪽을 500 mm 이동한 뒤 접합부·개구부·치수를 수정한다.
1:50 PDF와 DXF로 주석·블록·레이어 표현까지 검수한다.

## 테스트 개선 방향

기존 형상·트랜잭션 테스트는 데이터의 정확성과 복원을 확인하는 데
유용하다. 사용자 관점의 도구 상태, 포커스, 커서 조작, 반복 작업과
오류 피드백은 실제 UI 여정 테스트로 보완해야 한다.

특히 현재 `shortcutRouter.test.ts`는 선택 시 R이 회전으로 바뀌는 규칙을
정답으로 고정한다. 편집 정책을 먼저 정한 뒤, 단축키 함수뿐 아니라
첫 도형 생성→다음 도형 생성까지 검증해야 한다. 위 검수 과제를
브라우저 회귀 시나리오로 사용하고, 불필요한 패널 이동·도구 재시작과
원인을 알 수 없는 거절을 기록하는 것이 좋다.
