# CAD-EVAL-01 — Existing Design, Geometry and Intent Evaluation

2026-11-07. **과제·격리 실행·Native 채점·오류 환류 구현 완료. 실제 로컬 모델의 목표 달성은 실패.** 목표나 검증 기준을 낮춰 성공 처리하지 않았다. 학습, 제품 편집, 전체 모델 자율 생성은 수행하지 않았다.

## 과제와 설계 의도

작은 Box 치수 변경 대신, 기존 도구로 만든 합성 장비 케이스를 사용한다. 24개 객체/24개 피처 중 최종 솔리드는 열린 라운드 케이스, 통풍 덮개, 보호할 내부 참조 블록 3개다. 나머지 객체에는 원본 프로파일과 중간 피처가 포함된다. 24개 독립 부품이라는 뜻이 아니다.

- 케이스: 100×70 mm 스케치 → 30 mm Extrude → 수직 모서리 R4 → 두께 2 mm Shell → 바닥 Ø8 관통구 → 앞면 Ø10 깊이 2 mm 포트.
- 덮개: 기존 `vented-lid` recipe, 100×70×3 mm, 3행×5열 원형 구멍, 초기 지름 6 mm, 구멍 중심 경계 여백 12 mm. 월드 Z 32–35 mm.
- 내부 보호 블록: 60×30×4 mm, 월드 위치 [20,20,18] mm. 전자부품을 대신한 기하학적 보존 대상이며 실제 전자/열 해석 모델이 아니다.
- 요청: 기존 덮개에서 지름을 선택하여 총 개방 면적을 **700–800 mm²**로 변경한다. 모델에 답안 지름을 주지 않는다.
- 보존 의도: 외형·두께·배치·객체 ID·15개 구멍의 중심과 배열·live 참조, 케이스와 포트 및 내부 블록과 그 원본을 유지한다.
- 제약: 덮개 경계 잔여 폭 ≥8 mm, 구멍 사이 잔여 폭 ≥10 mm, 케이스 위 검사 간격 2 mm, 내부 블록 위 Z 간격 ≥10 mm.

명시적인 요구를 기존 `DesignStudy`/`DesignBrief`로 작성했다. 이는 **평가자가 작성한 합성 의도**다. 모델이 의도를 독립적으로 추출하는 능력을 별도 채점한 결과는 아니다. 재료·제조 공차·하중·체결 방식은 미정이며, 개방 면적을 냉각 성능으로 해석하지 않는다. 2 mm 간격은 검사 자세이며 밀폐된 조립 상태를 인증하지 않는다.

이번 범위는 **복잡한 기존 설계의 제한된 재설계**다. 전체 케이스 생성은 기존 Native planner를 실행한 fixture 준비이며 AI가 생성한 것으로 집계하지 않는다. 여러 피처를 처음부터 자율 생성하는 과제는 이 카드의 검증 범위가 아니다.

## 구현·기존 코드 재사용

새 파일:

- `apps/web/evaluation/cadDesignEvaluation.ts`: 과제, 합성 fixture, 설계 의도 평가기, 기존 read/replan 루프 연결.
- `apps/web/scripts/evaluateCadDesign.ts`: Native 대조 검증과 선택적 실제 Ollama 실행, 요청/응답·이벤트·해시·결과 파일 기록.
- `apps/web/tests/cadDesignEvaluation.test.ts`: 5개 집중 테스트.

재사용:

- `planCadToolPrompt`, `compileRecipe`: 기존 형상/스케치/구속/바인딩 생성.
- `copilotRequest` → `requestCopilotPlan` → 기존 `createLocalCopilot().plan()` → Ollama.
- `createCadToolSession`: 실제 모델 read와 검증된 scalar-edit 계획. 조회가 편집 권한을 확대하지 않는다.
- `prepareCadCommand`: 기존 UI Preview와 같은 CommandBus 준비/검증 경로. 복제 문서에만 실행하고 publication/History는 호출하지 않는다.
- `measureDocumentObject`: 실제 OpenCascade 형상 측정/유효성 검사.
- `designPreservationIssue`, `queryProfileExtrudeRelations`, Capability Ontology의 `driving-dimension-edit`/`profile-extrude-relations`.
- Native 직렬화 및 `readDesignScene`/`projectDesignScenes`/`designViewSvg`.

기존 사용자 작업 트리와 제품 코드를 수정하지 않았다. 새로운 CAD 명령, 온톨로지 저장소, CommandBus, AI 프레임워크를 추가하지 않았다. 실험을 제품 기능으로 등록하거나 기존 기능 지원 판정을 올리지 않았다.

## 실행·채점 계약

`요청 → 모델 read/명령 제안 → 격리 복제본에서 prepareCadCommand → Native 측정 + 의도 검사 → 오류 기록/기존 제한적 재계획`.

20개 조건을 모두 통과해야 `passed-native-preview`다. 기하학적 목표와 보존 조건은 가중 평균으로 상쇄하지 않는다. 미측정/커널 오류는 `unknown`/`incomplete`로 남긴다.

검사 항목은 문서·객체·피처 identity, 보호한 최종 객체 및 upstream 정의, 지름 driver만 변경했는지, 16개 입력의 live/resolved 관계, 외곽과 두께, 구멍 수/중심/균일 반지름, 개방 면적, 두 종류의 ligament, 세 BRep 유효성, 측정 bounds/Transform, 검사 간격, 내부 Z 간격, Native 체적과 독립 원형 구멍 면적식의 일치, 직렬화 왕복이다. 일반 곡면/다른 도면에 대한 범용 검증기가 아니다.

- 면적: 실제 현재 circle profile들의 πr² 합계. Native 체적 `(100×70 − 실제 구멍 면적)×3`과 별도 대조한다. 체적 공차 0.02 mm³.
- 배치/bounds: 0.001 mm 비교. 길이 조건의 부동소수점 비교는 명시적 수치 공차를 사용한다.
- 내부 여유: 월드 Z bounds 분리다. 범용 BRep 최소거리나 조립/충돌 인증으로 보고하지 않는다.
- 모델에는 현재 문서의 기능/관계 근거를 제공한다. 관계 16개 중 예시 2개와 생략 수/전체 live-resolved 여부를 명시해 전체 행을 숨겨 모두 보여준 것처럼 표현하지 않는다.
- 독립 Native 대조안과 정답은 모델 요청에 포함하지 않는다. 첫 실행 이후 보강한 오류 피드백은 실제 후보 지름·측정 면적·잔여 폭과 일반 원형 면적 공식만 포함한다.
- 원본 fixture JSON과 현재 프로세스의 editor document/History를 비교한다. `applyCadPlan`/`publishCadProposal` 호출은 0이다. 결과는 승인된 제품 편집이 아니라 검토용 후보 파일이다.

## 검증

이번 실행:

- 집중 단위/통합 **10/10 통과**, fail 0, skip 0: 새 평가 5개 + 기존 케이스 2개 + 기존 Profile/Extrude 관계 3개.
- 새 파일과 전이 의존성의 strict TypeScript 검사 통과.
- 아키텍처 검사 통과: **965 모듈**.
- 실제 LLM 실험 2회: **모두 목표 미달**. 위 실패를 보존했다.
- 모델 없이 수행한 Native 대조/산출물 생성 1회: 통과. 실제 모델 호출 0.

초기 새 테스트 실행은 3/5 통과, 2개 실패였다. 하나는 solver 결과 `8.000000000156245`를 정수 8과 strict equality로 비교한 테스트 오류였고 명시적 1e-6 수치 비교로 수정했다. 다른 하나는 의도적으로 객체를 제거한 입력이 직렬화 검증에서 throw되어 평가 기록을 남기지 못한 것으로, 직렬화 실패를 실패 criterion으로 기록하도록 평가기를 수정했다. 최종 위 10개 검사에서 모두 통과했다.

대표 브라우저, 실제 UI Apply/Undo/Redo, UI 파일 재열기, STEP 왕복, 전체 unit suite, 전체 browser audit, workspace build는 **미실행**이다. 이 카드에서는 제품 UI를 바꾸지 않았다. SVG는 기존 Native tessellation의 투영이며 브라우저 스크린샷이 아니다. 과거 카드 통과 기록은 이번 실행으로 집계하지 않았다.
