# 순차 구현과 검수 기록

> 단계 기록: 아래 구현·검수 수치는 해당 시점의 근거다. 최신 지원 범위는 [CAD-BASICS](../product/CAD-BASICS.md), 최근 전체 검수는 [PROJECT-STATE](../../PROJECT-STATE.md), 다음 실행 순서는 [NEXT-STEPS](../../NEXT-STEPS.md)를 따른다.

2026-10-03. 당시 결정한 아래 다섯 작업 흐름을 순서대로 구현하고 각 단계의
회귀를 확인했다. 기존 작업 트리의 변경을 유지했으며 커밋·배포는 하지 않았다.

## 구현된 흐름

1. 캔버스의 구동 치수·구속 표시, 대상 강조, 단위 입력, 관계 삭제,
   공개 충돌 진단. 치수의 원본은 스케치 제약이며 선택·미리보기·취소는
   문서와 History를 변경하지 않는다.
2. Move/Copy의 기준점→대상점, 지정 중심 Rotate, 절대·상대·극 좌표,
   Tab 길이/각도 잠금과 Enter/Space 명령 반복. XY/XZ/YZ를 검증했다.
3. 명시적 끝점/중심 스냅의 Coincident와 수평·수직 자동 구속.
   Alt 및 체크박스로 억제한다. 보조선은 스냅·구속에 참여하고
   프로파일에서는 제외된다. 일반 도면에는 지속 구속을 강제하지 않는다.
4. 외곽·구멍·독립 영역과 중첩 섬의 분류, 교차/접촉 경계 거절,
   실제 Worker 돌출 미리보기, 영역 선택·깊이 입력·확정/취소.
   여러 영역은 하나의 compound 피처가 된다. 구멍 경계도 live 입력에
   포함되며 폭·지름·간격 편집은 연결 솔리드와 함께 한 Undo로 복원된다.
5. 레이어 색상·Continuous/Dashed/Center·물리적 선굵기, 문자,
   연속 연관 치수, 구멍을 제외한 연관 해치, 선택에서 블록 정의 및
   위치·회전 삽입. `2D → Drafting`에서 접근하며 레이어 스타일은
   Layers 패널에서 편집한다. 6,000×4,000 평면과 150mm 벽의 연결 및
   문·창 개구부는 하나의 파라미터 모델에서 생성·수정한다.

브라우저 검사로 발견한 추가 오류도 고쳤다. 앱의 비동기 상태 갱신이
그리기 이벤트를 재등록해 입력 중인 좌표를 지우던 문제를 수정했다.
PDF는 도면의 위/아래 방향을 보존하고, 치수 레이블을 가운데 정렬하며
치수선과 문자 사이에 여백을 둔다. 고정 축척이 종이를 넘으면 출력 전에
안내한다. 한글을 `??`로 바꾸던 기존 테스트와 구현은 수정했다.

## 검수

최종 결과: Node 316개, 별도 UI·Worker 64개 통과. `pnpm build`와
Git diff의 공백 검사도 완료했다. 브라우저 집계는 기존 흐름 15,
캔버스 11, 기준점·자동 구속 15, 구멍 영역 8, 건축 납품 15개다.

- Node 테스트: 전체 실행으로 기하·체적·참조·완전한 문서 Undo/Redo,
  실패 시 revision·History 보존을 확인한다.
- React/브라우저: 기존 편집, 캔버스 구속, 기준점 조작, 구멍 돌출,
  건축 표현·납품의 다섯 페이지를 실제 Worker와 함께 자동 실행한다.
  Node 테스트와 별도 집계한다.
- 기계 과제: 100×60×8 판의 4개 관통 구멍. 폭 120, 첫 구멍 지름 12,
  다른 구멍 중심 X=100으로 편집 후 실제 삼각형 체적을 확인한다.
  원의 tessellation 오차에만 작은 허용 오차를 두며, 경계 교차 편집은
  원자적으로 거절한다.
- 건축 과제: 6,000×4,000, 벽 150, 문 900, 창 1,200.
  문·창 중심을 각각 500mm 이동하고 치수와 벽 연결을 검사한다.
  1:50의 4,000mm가 종이에서 80mm임을 수치로 확인한다.
- 실제 브라우저가 만든 1:50 한글 PDF를 Poppler로 렌더링해 검수했다.
  별도 `pypdf`로 페이지와 이미지 구조를 확인했다. 도면 선은 벡터이고
  한글 레이블만 브라우저 설치 글꼴로 고해상도 이미지화한다.
- `ezdxf 1.4.4` 독립 검사에서 평면과 블록 DXF의 오류와 자동 수리 모두
  0건. 한글 TEXT와 INSERT의 위치 2,000/1,000·회전 90°도 확인했다.

재현 명령:

```powershell
pnpm --filter @agent-webcad/web test
pnpm --filter @agent-webcad/web test:browser
pnpm build
pnpm --filter @agent-webcad/web test:browser -- --artifacts
```

마지막 명령은 검수 샘플 PDF, DXF 두 개, 원본 WebCAD JSON과 plot 계획을
`output/pdf/`에 저장한다. 브라우저는 별도 임시 프로필과 로컬 테스트
서버를 사용하며 종료 시 자체 프로필과 프로세스만 정리한다.

## 출력과 편집 경계

- DXF는 R2007 UTF-8, 레이어 스타일, TEXT, BLOCK/INSERT를 보존한다.
  연속 치수·해치는 선과 문자로 출력되며 DXF 재가져오기 시 원본
  연관성은 복원되지 않는다. 연관 정보는 WebCAD JSON에 보존된다.
  단순 블록만 지원하며 중첩 INSERT는 경고와 함께 제외한다.
  XY 외의 원·호는 현재 DXF에서 샘플 선으로 표현된다.
- PDF 한글은 이미지와 Unicode ActualText를 사용한다. 벡터 글꼴을
  임베드하는 출력과 여러 장의 도면 구성은 다음 납품 개선 과제다.
- 구멍은 현재 돌출에서 지원한다. 회전·스윕·로프트는 구멍 포함 입력을
  명시적으로 거절한다. 교차하는 영역을 자동 분할하거나 접촉 경계를
  임의로 합치지 않는다.
- 평면 샘플은 하나의 방과 문·창 개구부 모델이다. 전체 건축 벽 네트워크,
  다중 방 자동 연결, 문/창 라이브러리와 자유로운 개별 벽 편집은 별도다.
- 새 구속은 Coincident/Horizontal/Vertical에 한정된다. 평행·접선·동심,
  Mirror/Pattern, 면 위 스케치, 엣지 참조 복구 및 큰 문서 성능은 남아 있다.

이 기록은 대표 작업 흐름과 회귀 검수 결과다. 실무자 작업 시간과
복잡한 프로젝트의 전체 납품 품질을 검증했다는 의미는 아니다.
