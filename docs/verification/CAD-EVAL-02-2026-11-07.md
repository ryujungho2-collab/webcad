# CAD-EVAL-02 — Edge-relative Mounting Intent

2026-11-07. **실제 로컬 모델이 문서 조회 후 유효한 재설계안을 Native Preview까지 전달했다.** 전체 모델 자율 생성, 사용자 승인/Apply, 물리적 체결·강도 인증으로 확대 해석하지 않는다. 이전 통풍 과제의 실패 기록은 그대로 보존한다.

## 다른 과제

합성 문서는 8개 객체/8개 피처로 구성한다. 네 구멍의 2D 프로파일과 파라메트릭 Extrude, 내부 장치 참조 블록, 이웃 장애물이며 최종 솔리드는 3개다. 기존 `mountingPlatePlan`과 `prepareCadCommand`로 fixture를 생성한다. 이 준비를 AI 생성으로 세지 않는다.

초기 장착판은 120×80×4 mm, 구멍 4개 Ø6 mm, 인접 가장자리에서 중심 여백 12 mm다. 판의 월드 Z 범위는 8–12 mm다. 보호할 장치 블록은 [40,25,14]에서 40×30×6 mm, 이웃은 [190,0,8]에서 20×80×4 mm다.

모델 요청은 **현재 폭을 조회한 뒤 40 mm 넓히기**다. 완성값 160 mm나 정답 명령은 요청에 넣지 않는다. 현재 값은 기존 선택 객체의 실제 scalar contract와 `cad.inspect`로 제공된다.

설계 의도:

- 왼쪽 datum과 객체 배치를 유지하고 오른쪽으로 넓힌다.
- 깊이·두께·구멍 개수·지름·중심 여백을 유지한다.
- 구멍들은 **새 판 중심**을 기준으로 대칭이어야 한다. 오른쪽 구멍은 가장자리를 따라 이동해야 하므로 모든 구멍 좌표를 고정하는 것이 보존 의도가 아니다.
- 내부 장치/이웃 객체의 형상·배치와 원본, 선택 객체 ID 및 live 프로파일 참조를 유지한다.
- 장치와 판의 Z 간격 ≥2 mm, 판과 이웃의 X 간격 ≥25 mm를 유지한다.
- 재료·하중·제조 공차·체결 규격은 미정이다. 간격 측정은 축 방향 bounds 분리이며 범용 최소거리나 물리 검증이 아니다.

기존 `DesignStudy`에 평가자가 이 의도를 작성했다. 모델의 별도 의도 추출 응답을 평가한 결과는 아니며, 제출한 실제 변경의 의도 준수를 검사한다.

## 구현과 재사용

- 추가: `apps/web/evaluation/mountingPlateEvaluation.ts` — fixture/요청/20개 Native·의도 검사.
- 추가: `apps/web/tests/mountingPlateEvaluation.test.ts` — 새 과제 검증 3개.
- 변경: `apps/web/evaluation/cadDesignEvaluation.ts` — 이전 캡처 세션·검증·재계획 루프를 `runCadEvaluation`으로 공유하고 통풍 과제 wrapper를 유지했다.
- 변경: `apps/web/scripts/evaluateCadDesign.ts` — `--task=mounting-plate` 선택만 추가하여 기존 모델 연결·호출 예산·trace·hash·산출물 경로를 재사용한다. 성공한 실제 모델 후보도 별도 `model-preview-*.svg`로 저장한다.

제품 CAD 명령·Gateway·CommandBus·커널·UI를 변경하지 않았다. 기존 사용자 변경과 지난 과제 파일을 보존했다. Capability Ontology 및 기존 Profile↔Extrude 조회를 읽기 전용 근거로 사용한다. 학습을 실행하거나 새 제품 capability를 등록하지 않았다.

## 실제 모델 실행

모델: Ollama `qwen3-coder-32k:latest`. 한 번의 실제 실행에서 호출 2회, Native 후보 1회, 재계획 0회, 수리 호출 0회다. 설정 상한은 실제 모델 호출 4회였다.

1. `cad.inspect`로 실제 선택 plate ID 조회.
2. `solid.parameter`로 실제 `plate_6359d0fb180046b684b862fef8b45d4f_width`를 **160**으로 제안.
3. `createCadToolSession.plan` → 기존 scalar command → 복제 문서의 `prepareCadCommand` → 20/20 검사 통과.

| 실제 결과 | 측정 |
|---|---:|
| 폭 | 120 → 약 160 mm |
| 깊이 / 두께 | 80 / 4 mm 유지 |
| 구멍 | 4개, Ø6 mm 유지 |
| 왼쪽 두 구멍 X | 12 mm 유지 |
| 오른쪽 두 구멍 X | 108 → 약 148 mm |
| 구멍 Y | 12 / 68 mm 유지 |
| 중심의 가장자리 여백 | 12 mm 유지 |
| 장치 Z 간격 | 2 mm |
| 이웃 X 간격 | 약 30 mm |
| 판 체적 | 50,747.61065788286 mm³ |
| 독립 계산식 체적 | 50,747.61065788307 mm³ |

모든 BRep의 Native 유효성은 `valid`다. 체적 공차는 0.02 mm³, bounds/중심 길이 비교 공차는 0.001 mm다. 명령은 기존 width 변수 하나만 변경하고 바인딩이 프로파일·구멍 중심·BRep을 재계산한다. AI가 각 구멍을 별도 이동한 것이 아니다.

엔진 보고 토큰: 입력 2,471+2,442=**4,913**, 출력 90+93=**183**. `num_ctx=16384`, 출력 예약 1024, `truncate=false`; 두 응답 모두 `done_reason=stop`이다. 이번에 잘림을 관측하지 않았고 실제 유지 토큰을 별도로 계측한 것은 아니다. Gateway 시간은 2,489/2,078 ms, fixture/대조/투영 생성을 포함한 runner 총 시간은 **7.407초**다. 보장되는 성능 수치가 아닌 단일 관측이다.

원본 hash 전후 동일:

`3624a74fc9240486657ecb2fcfe5ef31a61606d4d2db5406bb4bbac64b770be7`

원본·현재 프로세스의 editor document·History는 불변이며 Editor Apply 호출은 0이다. 결과는 검토 가능한 `.webcad.json` 후보로 저장했다. 사용자가 승인했다고 가정하지 않는다.

## 판단

기존 관계와 바인딩이 잘 표현된 장착판에서, 실제 모델이 현재 값을 근거로 지원되는 명령을 선택하고 설계 의도를 유지하는 재설계에 성공했다. 한 번의 scalar-edit 과제 성공이며 복잡한 신규 설계·자율 Assembly·임의 최적화 능력을 증명하지 않는다.

앞선 통풍 면적 과제는 여전히 실패다. 다른 과제/입력/추론 요구이므로 이번 성공을 이전 실패의 해결이나 모델 일반 성능 향상, 온톨로지 성능 향상으로 보고하지 않는다. 다음 과제를 자동 시작하지 않았다.
