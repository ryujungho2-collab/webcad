# CAD-ORDER-01 — 2D 벡터·해치 표시 순서

2D 작업 공간의 표준 작업 평면(XY/XZ/YZ)에서 일반 최상위 벡터와 해치에 적용한다. 사용자는 객체를 선택한 뒤 Ctrl+K에서 **Bring drawings to front** 또는 **Send drawings to back**을 실행한다. **Send hatches to back**은 선택 없이 현재 평면의 보이는 잠금 해제 해치를 대상으로 한다. 대상 내부의 상대 순서를 유지한다.

| 경로 | 계약 |
| --- | --- |
| 명령 | 기존 팔레트 → `reorder-drawing` 검증 → CommandBus → History 한 항목. 잘못된 선택이나 동일 순서는 문서를 변경하지 않는다. |
| 상태 | `CadObject.drawOrder`는 선택적 정수 우선순위다. 기본값과 동률은 기존 배열 순서를 따른다. `rootObjects`, 레이어 소유, 참조, 피처를 그대로 둔다. 일반 기하 재생성 없이 변경을 게시한다. |
| 파일 | 기존 직렬화 버전에서 선택적 속성을 보존한다. 해당 속성이 없는 파일도 읽으며, 이전 앱은 새 표시 순서를 적용하지 않는다. 이전 앱 교환은 실행하지 않았다. |
| 뷰포트 | 지원 객체의 선과 채우기를 한 합성 경로에서 순서대로 그린다. 3D 및 다른 작업 평면으로 전환하면 기존 재질 상태로 복원한다. |
| SVG | 활성 평면 SVG가 같은 상대 순서를 사용한다. 일반 아트보드와 프레임 출력도 해당 범위의 벡터 슬롯에 순서를 반영한다. |
| PDF | 활성 평면의 기존 벡터 Plot은 동일한 순서로 스트로크를 기록한다. 해당 작성기는 채우기·불투명도를 출력하지 않으므로 채우기에 의한 가림을 재현하지 않는다. |
| DXF | 표시 순서 호환은 이번 작업 범위 밖이다. |

선, 폴리라인, 사각형, 원, 호 및 해치가 대상이다. 잠금·숨김·다른 평면·없는 ID를 섞은 선택은 원자적으로 거부한다. 이미지와 주석 등 지원 범위 밖 객체와의 교차 순서는 별도다. 기존 이미지 명령은 `rootObjects`의 이미지 슬롯을 사용한다.

구현은 `drawOrderCommands.ts`, `drawOrder.ts`, `drawingStackRender.ts`, `CadViewport.tsx`, `exportModel.ts` 및 기존 App/팔레트 연결을 따른다. 벡터 채우기의 원래 색을 재질에 저장하여 선택 해제 후 정확한 색을 복원한다.

`general-draw-order`를 `supported / document-edit / command-bus`로 갱신했다. 087의 과거 이미지 전용 매핑 및 부분 지원 판정과 089의 과거 미확인 판정은 그대로 유지했다. [현재 인벤토리](WEBCAD-CAPABILITY-INVENTORY.json)

## 이번 검증

| 검사 | 결과 |
| --- | --- |
| 집중 단위·통합 테스트 7개 파일 | **58/58 통과**, skip 0. 다중 대상 순서, 원자적 거부, 소유·참조 불변, History, 저장, SVG/PDF 선 순서, 이미지와 온톨로지 포함 |
| Edge `drawOrder` | **10/10 통과**. 실제 캔버스 겹침 픽셀, 내려받은 SVG 순서, Undo/Redo, 네이티브 파일 내려받기 및 재열기 |
| Edge `imageWorkflow` | **47/47 통과**. 기존 이미지 정렬 검토·적용·Undo 및 출력 포함 |
| Workspace 빌드 | **통과**. Vite 번들 크기 경고 유지 |
| 아키텍처 검사 | **통과**, 946개 모듈 |
| `git diff --check` | **통과** |

PDF는 `planPlot`의 선 순서와 `encodePdf`가 생성한 PDF 스트로크 명령을 검사했다. PDF 뷰어에서의 픽셀 비교, 표시 순서가 적용된 아트보드·프레임의 별도 브라우저 검사, 구버전 앱 교환, DXF 표시 순서 및 전체 suite는 미실행이다. 이전 카드의 검증 기록은 각각의 보고서에 남아 있다.

초기 브라우저 검사에서 채우기 색 복원 결함을 찾았다. 벡터 채우기에 원래 재질색을 저장하는 최소 수정으로 해결했다. Undo/Redo 픽셀 검사는 기존 선택 하이라이트를 해제하고 뷰포트가 해당 revision을 처리한 뒤 읽도록 정리했다. 최종 결과에 미해결 실패는 없다.

```powershell
pnpm --filter @agent-webcad/web exec tsx --test tests/drawOrder.test.ts tests/imageWorkflow.test.ts tests/ontologyCapabilities.test.ts tests/paletteCommandIds.test.ts tests/vectorStyle.test.ts tests/artboardAnnotations.test.ts tests/artboardPdf.test.ts
pnpm --filter @agent-webcad/web exec node scripts/browserChecks.mjs --page=drawOrder
pnpm --filter @agent-webcad/web exec node scripts/browserChecks.mjs --page=imageWorkflow
pnpm build
pnpm --filter @agent-webcad/web check:architecture
git diff --check
```

실행 로그는 `tmp/cad-order-01-*.txt`에 있다. 대표 브라우저 결과는 `output/verification/cad-order-01/browser-report.json`과 `red-in-front.png`에 있다.

CAD-LAYER-01·CAD-STYLE-01의 작업 트리 변경 위에 CAD-ORDER-01을 완료했다. 이 카드의 검증 기준으로 CAD-DIMSTYLE-01에 진입할 수 있다.
